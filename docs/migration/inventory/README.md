## 处置类别

| 类别 | 含义 |
|---|---|
| 保留并扩展 | 复用已验证实现，补齐新表示/目标能力；仍需通过新契约验证 |
| 替换生产路径 | 新实现承担完整职责；旧入口带明确标签保留到调用者迁完 |
| 历史隔离 | 只服务 rustc/LLVM 参考或旧实验，native 生产路径不调用 |
| 合并后退役 | 先证明新实现覆盖旧行为、迁完调用者和测试，再删重复实现 |

“历史隔离”的文件归入 `src/build/` 内的 reference 职责，不要求现在建子目录；先移除 native 生产依赖，等没有实验或调用者需要时再决定删除。

## 切换与退役步骤

1. **登记调用者：** 搜索入口、库导出、内部函数、测试和脚本的引用。一个旧函数服务多条链时，先拆开身份/配置。
2. **加显式新路径：** 用冻结的选择方式（不在本清单另造 CLI 开关名）。legacy 和 oracle 只由用户/测试显式选择。
3. **隔离产物：** 旧 Graph 缓存、新语义缓存、LLVM reference 产物分别使用 namespace/schema/输出目录。
4. **迁移行为与证据：** 源码到真实执行的对照；旧/新入口的测量分开。对象字节可以变，行为、ABI 和确定性不能变。
5. **切换默认：** 满足阶段门禁后逐个调用者切换，取消、错误、缓存 miss、cold build 一起验证。
6. **删除旧实现：** 无生产依赖、外部使用者有迁移说明、旧测试的语义都有新归属、参考实验仍可重放。临时兼容入口要有退出条件。

整张表不会因目录重排一次性变成 `verified`。每完成一项，记录：旧文件/符号、新职责、任务 ID、调用者清单、测试去向、验证证据、来源许可、退役条件、当前状态。

## 责任

- 集成（I）：入口、公开导出、跨职责契约。共享文件不同时交给两个未协调的任务。
- 前端（A/B）：parser/Body 切换和接受/拒绝矩阵。
- 后端（C/D）：图、ABI、机器码、对象。
- 构建（E）：任务预算、取消、发布、缓存 schema、可重放证据。
- 一个旧文件分散到多个目标职责时，先由一个任务拆出行为接口，再把互不重叠的部分分给其他任务。
- 新增或删除源码文件后重新跑覆盖检查；遗漏项记为 `planned`，不从统计中静默删除。
