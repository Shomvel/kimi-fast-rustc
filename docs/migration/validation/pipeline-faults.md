# 调度、缓存与取消的故障测试

对应设计：[build-pipeline.md](../architecture/build-pipeline.md)、[cache.md](../architecture/cache.md)。

## 调度确定性

串行参考运行与 jobs=1/2/4、不同队列容量、延迟扰动下结果一致。比较输出字节、稳定诊断和来源清单，而不只是退出码。

主动制造：递归定义、trait 循环、迟到依赖、超大单函数、队列满、上游失败、消费者提前退出、取消。大图时检查内存上限和回压。

## 缓存

- 禁用 / cold / warm 三种路径结果相同；cold、miss、hit 分别计时，不只展示热缓存。
- 逐项改变版本、target、cfg、语义输入、泛型体、trait impl、宏卫生、优化选项、被调用者、布局、panic/overflow，确认发生预期失效。
- 损坏、部分写入、旧 schema、错误依赖身份不得命中。
- 失败不留下会被当成成功的清单。

## 失败与取消

- 默认 fail-fast 与后续的 `--keep-going` 分别测试。
- 任务失败后，已启动的工作和所有等待者在有限时间内收束。
- 超时是失败，不能当作正常取消。
- 取消/失败不发布半成品。
