# 性能比较协议

## 基线与候选

- **基线：** 固定版本的 stock rustc+LLVM。
- **候选：** 固定版本的 kfrc 完整链。
- 源码、lockfile、features、edition、target、CPU 特性、环境一致；panic、overflow、debug、strip、LTO 明确记录。
- 两种配置分开报告：常规 portable release；双方在相同约束下各自的最佳 release。
- 编译器自身的构建模式（含 PGO/BOLT）与目标程序的优化分开记录，不拿 debug 候选比较。

## 编译时间

场景分别测：冷构建、no-op、叶子函数修改、公开接口修改、cache miss、cache hit。依赖预先下载，源码输入和系统缓存策略固定。

记录：完整构建墙钟、CPU 时间、进程树峰值内存、任务等待/执行时间。

收益目标在 M0/M5 测出瓶颈后再定，不预先承诺倍数。每个关键 workload 单列，带置信区间和内存代价。SoN pass 微基准只用于解释瓶颈，产品收益要有整链数据。

## 产物体积

对象大小、可加载节大小、完整文件大小，并提供等同 strip 后的结果——去掉调试信息不算代码生成质量提升。

## 运行时间

- workload 覆盖 ripgrep 的不同搜索/匹配模式和输入规模，以及 Cargo 的解析、依赖操作等实际工作。
- 先验证输出等价，再采样。
- 批次足够长以压低进程启动噪声；多轮交错或随机臂顺序；保留全部原始值、warmup 和排除样本的理由。

## 判定

目标：每个代表 workload 的 runtime 和 size 比值 `candidate / baseline ≤ 1.0`。

- runtime 用预先约定的统计量和单侧置信上界判断；上界跨过 1 记为“证据不足”，不因中位数略小就宣布不退化，也不临时放宽到 5%。
- 体积是固定产物的直接度量。
- 来源或语义不等价时，整组比较无效。
- 配置不公平、噪声过大时先改进实验设计，不删 workload、不降优化要求。

## 历史数字

仓库 [VALIDATION.md](../../VALIDATION.md) 中的 705/715 等计数是历史记录，本计划不重新认证，也不把不同版本、主机、范围的计数相加。
