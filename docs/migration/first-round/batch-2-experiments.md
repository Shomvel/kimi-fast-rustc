# 批 2：控制流差分与语义实验（第 6–8 天）

任务：[T11](../roadmap/m1-vertical-chain.md#t11)、[T12](../roadmap/m1-vertical-chain.md#t12)、[T13](../roadmap/m1-vertical-chain.md#t13)，并扩充 T03/T09 的差分。

三条工作可以并行，各自满足输入门槛。两个实验如由不同人做，用隔离的实验目录或不重叠的文件所有权。

| 工作 | 输入与范围 | 输出与退出条件 |
|---|---|---|
| 控制流差分 | 批 1 的完整链；if/match/短路/loop 中已支持的组合 | 保存 seed、原始输出、最小反例；每种已支持组合有真实机器证据；未实现语法单列 |
| trait 实验（T12） | 固定上游来源、TypeId/约束模型；一个有约束泛型 + 对应的不满足约束反例 | 列出 canonical goal、参数环境、推导事务的必要依赖；最小闭包与 oracle 一致；记录未覆盖的 coherence/关联类型/递归规则 |
| borrow/drop 实验（T13） | Place/CFG/初始化事实契约；move、借用冲突、分支析构的小用例 | 有效/无效分类与 oracle 一致；drop 路径可检查；还不能执行时标为分析原型 |

## 实验要回答的问题

“我们的数据模型能否表达这组语义？需要迁移哪些依赖？”

- 不通过搬入大半 `TyCtxt` 或完整 query runtime 来绕过问题。
- 内存和析构执行链还不成熟时，可以交付事实提取/约束求解原型和缺口清单，但不算 M3 能力。
- T12/T13 `verified` 只表示实验按范围拿到了证据和成本结论。约定的观测没拿到，就不是 `verified`——缺口报告不能替代成功条件。
- 结论同时记录采用了和明确没采用的上游规则。

## 遇到错编译

按 [验证规则](../validation/README.md#发现错误时) 停止重复压测，静态排查相邻路径并批量修复。暂停新语法扩展；其他不依赖该错误的工作可以继续。
