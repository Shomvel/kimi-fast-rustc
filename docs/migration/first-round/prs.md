# 首批实现 PR 的切分

每个 PR 交付一个可独立验收的行为闭包，标题和说明围绕最终可观察的行为，并更新对应任务状态、来源记录和覆盖矩阵。

| 顺序 | 范围 | 必须交付 | 后续依赖 |
|---|---|---|---|
| PR 1：冻结基线与差分入口 | manifest、固定来源、成功/拒绝/已知失败 fixture、真实执行 harness | 干净输入到结果可重放；已知失败显式登记为 known-fail，不算通过 | 所有后续 PR |
| PR 2：最小生产链 | 批 0 契约 + 最小 AST → Body → SoN → ELF 纵向闭包 | 正例和拒绝例真正经过新入口；已知分支问题的最小路径正确 | 控制流扩展、语义迁移 |
| PR 3：控制流闭包与必要并行 | 已支持条件/循环/调用的组合；串行参考 + 有界并行准入 | 状态合并、真实执行、输出确定性；不顺带加缓存层 | M1 出口、M2 |
| 后续：语义实验转生产 | trait 或 borrow/drop 的一个闭包，分别提交 | 实验成本报告、明确范围、对应的完整验证 | M3 对应能力 |

- PR 2 过大时，可以先拆出可独立验证的公共表示/verifier；纯目录移动、空类型或 `todo!()` 接口不算迁移完成。
- 实验报告可以单独提交；没通过行为验证的实验代码不接入生产路径。
