# 批 1：最小纵向新链（第 3–5 天）

任务：[T04–T10](../roadmap/m1-vertical-chain.md)。沿一条完整路径推进，不一次铺开大量语法。

## 顺序

| 步 | 内容 | 完成证据 |
|---|---|---|
| 1 | A 把固定源码变成 AST/定义快照；B 用同一产物生成标量 Typed Body | 源位置、遮蔽身份、类型、CFG 可检查；无效输入在正确层拒绝 |
| 2 | C 接收 CheckedBody，统一处理分支/循环状态，构建并验证 SoN | Body 和图 dump 能对应；错误 Phi/控制依赖被 verifier 拒绝 |
| 3 | D 用现有机器码基础接入新图和 ABI；E 接通显式新入口 | 对象可链接；真实执行与 oracle 对拍 |
| 4 | 完整链存在后，扩展到调用/递归和首轮固定的控制流集合 | 每项新能力都有跨完整链用例；来源和 unsupported 清单同步 |

## 规则

- 不用占位返回值假装上游完成。接口稳定后，C/D 可以用人工 IR fixture 独立调试，结果标为“层内验证”，不计入源程序覆盖。
- E 可从批 0 开始完善 runner，但测试必须是源码行为对拍，不能写成镜像实现。
- 先有串行参考执行，再接最小的函数级有界并行。并行准入的前提：串行正确、输入产物不可变、符号身份稳定。这一步不做动态 trait 调度和跨 crate 通知。

## 出口

- 至少一个成功用例和一个拒绝用例穿过新的公共入口。
- 分支状态回归运行正确。
- 日志能区分新链和旧链；未接入的能力显式拒绝。

只做到 AST/Body/图 dump 算部分完成，不算 M1 通过。
