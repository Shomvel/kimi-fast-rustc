# 批 3：验收、交接与重估（第 9–10 天）

任务：[T14](../roadmap/m1-vertical-chain.md#t14)。

## 验收

集成人选定冻结候选，由 E 在干净环境重放；实现者提供命令和产物，不只是口头确认。检查：

- 源码与二进制一致、走显式新入口
- 真实 x86 正例、拒绝例、控制流回归
- 必要的 verifier
- 串行/并行结果一致
- 来源记录和已知缺口

本轮不出 Rust 性能结论。可以记录阶段耗时和峰值内存来定位结构成本，但不据此宣称 ripgrep/Cargo 加速。运行覆盖只计完整新链上的样例；人工 IR、混合 bootstrap、分析原型分别计数。

## 交接记录（提交到仓库）

1. 接受的源码 commit、构建命令、oracle/候选哈希、执行环境与 target。
2. 任务状态表及证据链接；部分完成的任务写清未完成部分，不用总百分比代替。
3. 公共契约版本、主动偏离来源实现之处、移植来源与许可。
4. 新链的已支持 / 明确拒绝 / 尚未验证集合；干净重放的已知失败。
5. trait 与 borrow/drop 实验的依赖成本、模型缺口、是否进入正式迁移。
6. 下一组可独立验收的 PR、前置条件、负责人、所需验证资源。

## 之后

M1 出口没完全满足时如实保留未完成状态，可以记录“某个纵向样例已验证”。时间盒结束后按实际依赖和缺陷密度重新估算，不按 agent 数量换算剩余工期。
