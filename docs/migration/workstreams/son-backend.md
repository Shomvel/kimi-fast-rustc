# SoN、native 后端与对象迁移工作流

状态：计划，未实施。共享表示以 [架构契约](../architecture.md) 为准。此文件负责从已检查函数体到目标对象的工作，不重新定义前端类型系统、借用规则或任务调度协议。

`SB-01` 至 `SB-08` 是此工作流内的稳定任务标识。上层批次可以引用这些标识，但每项交付仍需具备输入、结果和验收证据。不得把“文件已经拆分”当作迁移完成。

## 1. 现状与保留资产

当前 [son.rs](../../../src/son.rs) 的节点支持整数运算、函数调用、控制流和 Phi，`memory` 被注明为预留状态输入；这不是已实现的通用 Rust 内存语义。[x86.rs](../../../src/x86.rs) 的 Load/Store 用于栈 spill，不能用它证明用户指针读写已经支持。

可优先复用的资产为 [cfg.rs](../../../src/cfg.rs) 的 CFG/liveness、[placement.rs](../../../src/placement.rs)、[regalloc.rs](../../../src/regalloc.rs) 的线性扫描算法、[x86_encode.rs](../../../src/x86_encode.rs) 的已验证指令编码、[elf_reloc.rs](../../../src/elf_reloc.rs) 的基本对象/重定位逻辑，以及针对这些能力的回归。复用前核对新类型与控制语义，不将所有当前测试通过直接解释为新架构正确。

现有函数并行见 [parallel_native.rs](../../../src/parallel_native.rs)，完整程序对象见 [native_program.rs](../../../src/native_program.rs)，缓存见 [native_cache.rs](../../../src/native_cache.rs)。迁移时函数身份必须由 `InstanceKey` 驱动，替代裸声明序号或名称作为完整身份的假设。

## 2. 输入与输出接口

后端输入是已检查、已实例化、具备具体类型和目标布局的函数体。必须包含正常/异常控制路径、运行时检查、drop、调用约定、target features 和有效的源位置映射。后端不补猜类型，也不能删除前端尚未实现的检查。

后端输出包含对象或对象片段、符号/重定位/数据描述、能力记录以及需要链接的 runtime 符号。编译失败时不得发布可被重用的对象。未知 ABI、intrinsic 或指令必须诊断为未支持能力，而不是生成为常量或忽略。

| 后端内部产物 | 完成时需要验证 |
|---|---|
| SoN 图 | 节点类型、输入类型、Phi 对应、支配与可达性、效果链、循环封闭 |
| 放置后的图/块 | 每条控制路径保留效果；节点移动满足支配及效果约束 |
| Machine IR | 操作数宽度/类别、指令固定寄存器、调用 clobber、控制与 flags 依赖 |
| 分配后机器函数 | 所有虚拟值有位置、栈对齐、callee-save、边上并行复制正确 |
| 对象 | section/symbol/relocation 一致，目标特征匹配、链接与真实执行成功 |

首轮效果模型采用一个保守内存/效果序列；返回、检查失败、unwind 和不可返回调用是可观察控制。未来区分读集合/写集合、别名类别或线程同步时，必须声明保守未知状态及合并规则。

## 3. 分阶段工作包

### SB-01：锁定表示与 verifier

- 阶段：M0–M1；依赖：共享 ID、类型、Typed Body 和 TargetSpec 契约确定。
- 所有权：后端维护 SoN 图结构与 verifier；类型和布局规则由语义流提供，不能在后端再驻留一套不兼容类型。
- 工作：为节点结果和输入添加类型约束；图内引用与跨实例引用分开；明确控制、值、效果输入及多结果投影；定义循环未封闭状态与完成验证。
- 交付：表示说明、旧标量样本的显式迁移构造器、verifier、诊断式图 dump。规划落点 `src/son/graph.rs`、`types.rs`、`verify.rs`；旧 `src/son.rs` 在调用者迁移前保留兼容入口。
- 验收：损坏图在错误层被拒绝；正确循环/多前驱图通过；同一输入稳定 dump。故意破坏 Phi 前驱、跨图引用、类型或效果依赖的测试不允许进入编码。
- 回退：保持旧入口可运行，新图未验证前不替换生产调用者。

### SB-02：从 Typed Body 构建值与控制图

- 阶段：M1；依赖：SB-01 与语义流提供的标量 Typed Body。
- 工作：统一 if/match/短路/循环/return 的控制降低，按 CFG 前驱构造参数及局部值合并。处理多回边、break/continue 和不可达块；图构造时变量按 LocalId 识别。
- 交付：`src/son/build.rs`，每个函数体到 SoN 的单一生产入口；旧 parser-to-graph 路径仅作为小语言回归入口，不能自动 fallback。
- 验收：已报告的 `if` 分支赋值错误及同类组合通过 stock rustc 与真实 x86 执行对拍；覆盖嵌套循环、遮蔽、多个退出和不同分支赋值。同一个测试需能导出 Body、SoN 和机器码帮助定位。
- 回退：停止扩大控制语法，静态核查同类构造入口后批量修复，不靠不同语法分别维护 Phi 规则。

### SB-03：类型、内存与效果降低

- 阶段：M2；依赖：SB-02、语义流的 Place/布局，以及目标 ABI 初始契约。
- 工作：整数各宽度、截断/扩展、指针和聚合值；Load/Store、地址计算、静态对象、间接调用和数据初始化。运行时越界/溢出检查按配置保留，地址逃逸与未知调用保守处理。
- 交付：effect 节点与合并、目标布局查询接口、通用内存 lowering、数据对象描述。规划 `src/son/effects.rs`、`src/son/lower_place.rs`；名字可在接口冻结时调整。
- 验收：别名写后读、调用改写内存、结构体/数组字段、对齐、零大小值及跨函数返回聚合值对拍；错误优化不能跨检查、volatile 或未知调用移动访问。比较程序可观察结果，不读取结构体 padding 或未初始化值作为 oracle。
- 回退：禁用未证明安全的 load CSE/LICM，保守序列仍必须正确；不能通过禁用用户特性验收原始项目。

### SB-04：Machine IR、ABI 与线性扫描

- 阶段：M2–M3；依赖：SB-01 的类型契约，SB-03 的具体内存能力；标量 ABI 接入可在 SB-02 同期开始。
- 工作：固定目标的 ABI 分类、参数/返回、间接聚合传递、栈对齐、caller/callee-save；寄存器类别与分配约束、flags liveness、Phi 并行复制、spill。为真实需求添加浮点与 SIMD 寄存器，仍采用线性扫描。
- 交付：`src/machine/{ir,abi,lower,regalloc}/` 的职责拆分；迁移现有编码，保留验证过的算法；不增加 ILP list scheduler。
- 验收：C/Rust 两向 FFI 测试、不同宽度/聚合/浮点传参返回、栈参数、递归、跨调用活跃值、高寄存器压力、并行复制循环；实际机器执行结果与对照一致。
- 回退：每个新增类型/ABI 独立标记支持范围。未支持约定明确失败，不能按 i64 ABI 硬塞所有参数。

### SB-05：drop、panic、unwind 与 runtime 操作

- 阶段：M3–M5；依赖：语义流的 move/drop 与异常控制、SB-03/04。
- 工作：析构调用、检查失败、不可返回调用、panic 路径；按配置实现 abort 和 unwind。补齐异常表、personality/runtime 交互；原子/volatile/fence、TLS、必要 intrinsic 与 target feature 按目标依赖清单实现。
- 交付：效果和异常 lowering、平台展开信息、intrinsic 能力表及诊断，覆盖 native 依赖实际需要的语义。
- 验收：正常/早退/失败的析构次数与顺序，catch_unwind 支持范围、跨调用展开、线程同步 litmus 和 runtime 入口；不能把“编译成功但 panic 行为改变”当通过。
- 回退：早期 abort-only 能力必须显式列为阶段限制，拒绝要求 unwind 的输入；最终同等配置验收不能强制 abort。

### SB-06：对象、实例符号与跨 crate

- 阶段：M2–M4；依赖：实例身份与布局契约；基本静态数据与 SB-03 并行，完整 runtime 内容依赖 SB-05。
- 工作：代码/数据/只读数据、可见性、链接去重、所有所需重定位和 TLS。泛型实例、vtable、drop glue 与常量引用统一符号身份。metadata/rlib 外层格式由构建流负责，后端提供对象与符号契约。
- 交付：`src/object/`、确定性片段合并、可检验的 producer/target 标识、符号冲突与缺失诊断。
- 验收：系统链接器接受对象；跨 crate 泛型调用、共享常量、递归与符号冲突按语义处理；jobs 改变不改变确定性对象。真实链接和执行为必须项，readelf 只能辅助检查。
- 回退：旧子集对象与新格式使用不同标识，不读取不兼容缓存；不声称可直接复用官方 rustc 的私有 metadata。

### SB-07：优化规则迁移与机器码质量

- 阶段：基础规则从 M1 开始，广泛质量工作在 M5–M6；依赖：相关类型、效果及机器能力已验收。
- 工作顺序：纯值规则→控制与死代码→检查消除→受限内存/循环优化→内联/标量替换→目标相关选择/向量化。每个 pass 定义允许的输入、保持的不变量、预算和终止条件。
- 交付：逐项迁移 [son_optimize.rs](../../../src/son_optimize.rs)、[value_numbering.rs](../../../src/value_numbering.rs)、[loop_analysis.rs](../../../src/loop_analysis.rs) 与 [optimizer_pipeline.rs](../../../src/optimizer_pipeline.rs)；保存旧/新规则的差分结果。
- 验收：启用/禁用单个 pass 后均通过真实执行；浮点规则不默认 reassociate，整数规则按宽度与 overflow 模式验证，可能 trap 的除法不能任意消除。性能必须包括完整项目/代表工作负载，不把某 pass 的加速倍数解释成整体加速。
- 回退：关闭失败的优化规则保留正确 lowering，先处理错误类别；不能通过全部关优化获得最终性能通过。

### SB-08：并行、缓存与资源预算接入

- 阶段：初始函数并行 M1，依赖完备缓存与跨 crate 阶段 M4–M6；依赖：构建流提供预算/产物发布契约、SB-06 的确定性符号。
- 工作：每个实例独占图，跨实例并行；有界队列传递已验证产物；错误顺序确定，取消及时回传；统一 jobserver/worker 预算。缓存失效包括语义依赖、目标、ABI、内联摘要、配置和后端版本。
- 交付：旧 [scheduler.rs](../../../src/scheduler.rs)、[pipeline.rs](../../../src/pipeline.rs)、[native_cache.rs](../../../src/native_cache.rs) 中可用实现接入新任务，不建立第二套并行预算控制器。
- 验收：jobs=1 与多个 jobs 的结果/对象一致；取消/失败不发布半成品；大图时有内存上限和回压；cold/miss/hit 分别度量，不能只展示热缓存。失效测试覆盖被调用者、布局、target、panic/overflow 和 pass 配置变化。
- 回退：缓存不确定时回退重新编译，调度不稳定时使用同语义串行路径；不得回退到另一个代码生成后端。

## 4. 任务依赖与交付顺序

```text
共享类型/Body/目标契约
       └─ SB-01 → SB-02 → SB-03 → SB-05
                    ├─ 标量 ABI → SB-04 ─┘
实例/符号契约 ───────┴──────────→ SB-06
每类语义正确后 ─────────────────→ SB-07（按规则逐项）
构建预算/发布契约 + 确定性对象 ──→ SB-08
```

SB-07 与 SB-08 是渐进接入，不是等其他所有工作结束才开始。首批只接标量规则、单函数任务和显式无缓存路径。语言覆盖扩大前先把相应表示和 verifier 做完整。

## 5. 交付记录模板

每个工作包 PR 附带：固定输入与源 commit、实现来源及许可、修改的表示契约、支持/拒绝范围、真实执行命令与原始结果、图/对象指纹、剩余风险、回退方法。记录状态为 `planned`、`in_progress`、`blocked` 或 `verified`；没有验收证据不进入 `verified`。

首次动态验证发现某类错误后，暂停同类重复压测，静态查完整调用链和相邻规则，批量补回归与修复后再恢复。模型 evaluator、精确编码单测和图测试用于定位；最终语义结论以实际 x86 执行和源级对照为依据。

本工作流没有承诺量化编译加速。先证明正确性、资源上限和可重复性，再与固定 rustc+LLVM 配置比较完整编译时间、产物大小和 runtime。
