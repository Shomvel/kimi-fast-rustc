# 迁移验证与验收契约

状态：执行计划；本 PR 不实现编译器，也不声称重跑了完整测试或基准。与[架构](architecture.md)和[构建流水线](workstreams/build-pipeline.md)共同约束后续工作。

每个工作包交付必须能回答：哪种源程序通过了什么完整路径，使用哪个源码/二进制，和谁比较，实际观察到什么。模块测试通过不等于 Rust 语言兼容，微基准加速不等于整项目编译更快，编译成功不等于运行正确。

## 验证层次

| 层次 | 验证对象 | 通过条件 |
|---|---|---|
| 输入与语义 | AST、解析/展开、类型/trait、borrow/move/drop | 有效输入可接受；无效输入按拒绝类拒绝；不要求与 rustc 诊断字面相同 |
| 中间表示 | Typed Body、SoN、Machine IR | 类型、定义/使用、控制流、Phi 和副作用不变量成立 |
| 单个迁移闭包 | 一组相互依赖的语言功能 | 源码经新完整链运行，与 rustc 参考输出一致 |
| 工具链 | 多 crate、ABI、sysroot、Cargo、host 工具 | 依赖身份、行为、产物来源及失败恢复全部可验证 |
| 产品 | ripgrep/Cargo 的冻结工作负载 | 功能通过，再判断编译时间、运行时间、体积与资源 |

## 首个永久回归：有状态 if 表达式

以下为合法 Rust，`check(false)` 应为 21，`check(true)` 应为 12：

```rust
pub fn check(flag: bool) -> i64 {
    let mut x = 1;
    let y = if flag {
        loop { x = 2; break 10; }
    } else { 20 };
    x + y
}
```

2026-11-08 审查在 Linux x86_64 上执行 kfrc 直接生成的 ELF，观察到 `false=20, true=12`，stock rustc 参考为 `false=21, true=12`。相关 [frontend.rs](../../src/frontend.rs) 的 `parse_if_expression` 只合并表达式值，缺少分支可变绑定状态的完整合并。现有 [machine_eval.rs](../../src/machine_eval.rs) 也暴露了该差异，但真实执行才是此次行为证据。

来源限制必须随问题保留：审查复用了工作区现有 debug binary 和 rlib，工作树有五个未提交文件，不能把该结果描述成“clean HEAD 构建已复现”。HEAD 是 `44c9d80b02ab140d7edf5348b6946d8122d842b6`，所检查的 `parse_if_expression` 函数与 HEAD 一致。二进制 SHA-256 为 `9f9e730d3ddc9fcc233297399cab3bd5e813c325f3216513a9b97c0913ed3c0d`；执行对象 SHA-256 为 `c7f4a5eaeeef8e97d3aa57e3520d709b818db340815c98bd098fabe9127775cb`。这是已有审查观察，不是本计划 PR 新运行的结果。

M0 应重新在冻结源码上构建，再将此源码、可调用驱动、参考/候选命令及原始输出作为公开可复现回归保存。修复同时静态排查 if/match/短路逻辑/loop 的绑定、控制和效果合并，覆盖嵌套、提前退出和多个赋值；不能仅特殊处理这个程序。

## 差分执行协议

1. 固定测试来源、seed、edition/cfg、目标、溢出/panic 语义和输入；记录源码摘要及支持能力标签。
2. stock rustc 与自有编译器分别编译同一程序。用于测试驱动的打印/断言若尚未支持，采用清楚隔离的 C ABI driver；不能把候选函数替换成 rustc 对象。
3. 在真实 x86_64 上执行，比较退出码、stdout/stderr、输出文件和必要的内存/FFI 观测。跨编译主机只能负责生成对象，不能用 machine evaluator 的成功替代目标执行。
4. 对不匹配保存原始输入、工具版本、产物、日志和阶段 IR；最小化后仍需用原错误条件复核，避免 reducer 把错误变成 UB。
5. 对无效程序比较拒绝类别：类型冲突、借用冲突、move 后使用、未初始化、约束无法满足等。未支持合法功能必须明确拒绝并记为覆盖缺口，不能等同于正确实现该功能。

生成器仅生成预先定义的无 UB、有确定观测结果的程序。规避数据竞争、未初始化读取、不合法指针、生命周期外使用及未经约束的浮点/随机/环境行为；不指定输出顺序的场景先定义可接受结果集合。源码不应依赖 rustc 当前恰好输出的未指定布局，布局验证应选择有契约的 `repr` 或明确的内部布局一致性检查。

新增语义的测试从完整输入跨公共编译入口执行；内部 graph verifier 用于缩短定位路径。借鉴上游测试时记录固定 commit、许可和适配差异，不能只搬实现而不搬边界用例。

## 必须覆盖的组合

| 主题 | 最低组合维度 | 可观测断言 |
|---|---|---|
| 控制与状态 | if/match/短路 × 赋值 × loop/break/continue/return | 所有路径的值和副作用一致，未执行分支无效果 |
| 整数 | 各宽度/符号 × cast × 边界值 × overflow 模式 | 截断、扩展、移位、除法和错误行为一致 |
| 内存 | 别名 × load/store × 调用 × 循环 | 读写顺序、对齐、有效性和可见结果一致 |
| 类型与布局 | struct/enum/tuple/slice × generic × `repr` | 大小/对齐、字段投影、判别值和跨函数传值正确 |
| ABI | 整数/浮点/聚合 × 寄存器/栈 × 直接/间接调用 | C driver 双向传参返回、callee/caller 保存、栈对齐 |
| 所有权 | move/drop × 分支 × 提前退出 × panic | 无效程序拒绝，析构次数/顺序及 cleanup 一致 |
| 泛型与 trait | 约束/关联类型 × 实例化 × 递归 × 动态派发 | 实例身份正确，vtable/drop glue 和约束行为正确 |
| 并发效果 | atomics/volatile/fence × 调用/优化 | 基于语言内存模型的合法观测；不能只用单线程模拟证明 |
| 构建 | host/target × proc macro/build script × cache × jobs | 产物来源无混淆，失效与错误取消正确 |

不用强行在 M1 实现整张表；每个阶段列出已实现、明确拒绝和未覆盖集合，并要求交付能力与组合验证同步。

## 图和机器表示验证器

Typed Body 检查每个 Place 的类型、投影/布局、局部初始化、终结指令和退出路径；所有权分析结果与 drop 显式化必须能关联回源位置。

SoN 检查 Node ID 有效性、数据类型、控制支配、Phi 输入与前驱一一对应、循环入口/回边、内存状态汇合、调用/检查/异常效果的连续性。内存节点缺失效果边、把 may-trap 节点移出其控制条件、把分支局部定义用于另一分支均应拒绝。允许的循环图与误构造的数据环要区别处理。

Machine IR 检查寄存器类别与约束、定义/活跃区间、spill 地址、调用 clobber、栈对齐、分支目标和重定位。验证器覆盖每个变换的入口/出口；在验证配置下强制启用。所有 verifier 通过仍不等于算法正确，最终以源程序实际执行对拍确认。

## 调度、缓存和故障验证

串行参考运行和 jobs=1/2/4、不同队列容量、延迟扰动下的结果必须一致。检查输出字节、稳定诊断和来源清单，而不只检查退出状态。测试应主动制造递归定义、trait 循环、迟到依赖、超大单函数、队列满、上游失败、消费者提前退出和取消。

缓存至少验证禁用/cold/warm 三种路径的相同结果；逐项改变版本、目标、cfg、语义输入、泛型体、trait impl、宏卫生及优化选项，应发生预期失效。损坏、部分写入、旧 schema、错误依赖身份不得命中；失败不得留下一份后续被视为成功的清单。

默认 fail-fast 与后续 `--keep-going` 分别测试；在任务失败后，已启动工作和所有等待者必须在有限时间收束。超时本身是失败，不能计成正常取消并通过。

## 性能比较契约

基线是固定版本的 stock rustc+LLVM，候选是固定版本的自有完整链。源码/lockfile/features/edition/目标/CPU 特性和环境一致；panic、overflow、debug、strip、LTO 目标语义明确记录。常规 portable release 与双方最优但约束相同的 release 分开报告。编译器自身的构建模式及 PGO/BOLT 与目标程序优化分开，避免拿 debug 候选或非等价工具链比较。

构建场景分别测冷构建、no-op、叶子函数修改、公开接口修改、cache miss/hit；依赖下载预先完成，源码输入和系统缓存政策固定。测完整构建墙钟、CPU、进程树峰值内存、任务等待/执行时间、对象及可加载节大小、完整文件大小。产物体积同时提供等同 strip 的结果，不能把移除调试信息当作代码生成质量提升。

运行时工作负载覆盖 ripgrep 的不同搜索/匹配/输入规模，以及 Cargo 的解析、依赖操作和有代表性的实际工作；`cargo metadata --no-deps` 只能证明该子命令场景。每个 workload 先验证输出等价，再采样；足够长的批次减少进程启动噪声，多轮交错或随机臂顺序，保留所有原始值、warmup 和排除样本理由。

最终目标仍为各冻结代表 workload 的 runtime 和 size ratio `candidate / baseline ≤ 1.0`。运行时间按预先约定的统计量及单侧置信上界判断；上界跨过 1 时写“证据不足”，不能因中位数稍小就宣布不退化，也不能临时放宽成 5%。无法严格证明持平时可报告估计值和不确定性，产品验收保持未完成。体积是固定产物的直接度量；来源或语义不等价则整组比较无效。

编译速度也报告完整置信区间和内存代价；M0/M5 测出瓶颈后再确定收益目标，不预先许诺 10×。每个关键 workload 单列，不能用平均数掩盖其中的退化。SoN pass 的微基准仅用于解释瓶颈，必须另有整链数据才可声明产品收益。

## 证据包与执行环境

每次验收保存 `manifest`、命令/配置、输入摘要、baseline/candidate 编译器与对象哈希、host/target/资源、产物来源、原始日志、差分结果及性能样本。清单标明测试通过/失败/跳过的具体集合，跳过项说明能力缺口。路径采用仓库相对位置或公开可访问的持续产物链接，不依赖某位开发者的本地绝对路径。

并行编译、profile 或正式测量遵循执行环境的 AGENTS 与相关技能要求。优先使用配置可核实的隔离环境，记录实际资源与模板/镜像身份；每个完整配置独立环境，原版/候选在同一环境串行对照。profile 与正式计时分开，监控由负责验证的 subagent 执行。凭据不进入日志或产物，不把不同宿主的绝对耗时混算。此文档规定验收契约，不固化内部 SSH 地址或凭据位置。

## 停止和恢复条件

首次暴露一类正确性错误后停止重复运行同类压测：冻结失败输入与源码，静态排查同类实现和邻接风险，批量修复与增加回归，再恢复差分。新的错编译、无效 Rust 被接受、旧缓存错误命中、产物来源不明或测试被静默跳过都阻止阶段晋级。

性能数据配置不公平、噪声过大或区间跨越阈值时停止收益宣称，先改善实验设计；不通过删 workload 或降低优化要求制造通过。某个迁移闭包过大时缩小交付范围并明确拒绝剩余能力，不用 rustc fallback 假装覆盖。阶段回退保留已验证模块、证据和可复现失败，不删除失败记录。
