# 调用点特化、私有整数转发与指针分支

本轮从已推送的 `7fb99c5b057e7ce7f8481f8ce9cd2e05f2d599e6` 接手，基线包含上一轮的地址去重、checked 结果共享、小型 product 传输和自然循环 16 B 对齐。新增收益均相对此基线计算；不与旧沙箱的绝对耗时或不同分母的比值拼接。

调用点特化只提取有类型的整数常量与有限层数的聚合字段事实。需要时在隔离的 callee 副本内展开小包装并清理，再按简化后的图沿用原内联门槛。候选源图最多 512 个存储节点，准备和内层内联各有节点预算；相同参数事实复用同一准备结果及类型导入。递归、ABI、CGU 可见性、常量地址身份和原实参的 RequireDefined 观察仍由原契约约束。无准备机会的调用先做廉价预算判断；常量清理后没有 Return 的候选保留原调用。

实际命中是 humantime 的 `char::to_digit(radix=10)`，callee 从 77 节点简化到 37 节点，三个调用点成功内联。`two_digits_inner` 内相同事实命中缓存。base64 的 `read_u64`、decode chunk 和 humantime 单位字符串比较仍未打通；前者的长度事实跨越了 Result/call 边界，不能把本轮特化写成已完成这条包装链。

私有整数转发只处理完全包含于已有整数写入的读取。完整整数存储的字节可在当前唯一的 little-endian x86_64 目标上用逻辑移位和截断取得，外部读取范围不扩大。地址逃逸、部分覆盖、未初始化字节、不同入边写入、新生命周期和循环仍保留原有保守边界；不将指针、bool、char、float 或 padding 当作普通整数位串。

转发后的同源位片段若移回原位并按位或，合并为原整数的 mask；覆盖全部位时恢复原值。保留 signed 窄扩展、不同来源和带算术承诺的移位。真实 Rust fixture 中，三个窄读取函数从 8–9 条指令降为 3 条，disjoint-store 从 10 条降为 3 条，完整字节重组从基线 30 条降为 `mov; ret` 两条；部分重叠写入后的快照用例保留原路径。W4 首版重组反而生成 36 条指令，已单独留证，不将其中间版本计入最终收益。

薄指针 Eq/Ne 的直接分支也已实现并完成原生验证，但累计候选的 semver requirement 在固定 CPU 的 21 轮中稳定回退约 4.9%。撤下这三个文件后，大回退消失；因此最终源码不包含该优化，独立补丁与全部数据保存在本轮实验目录。

最终候选正在对照统一函数对齐策略验收。仅提高 function section alignment，循环和 encoder 的 16 B 对齐不变；按固定机器码的布局对照选型，并单独核算最终 executable 的对齐填充成本。最终性能与源码指纹完成后补齐本段。

同一任务 E2B 实例内重建 Rust 1.94.1 / LLVM 21.1.8、MIR0 sysroot，四库 O3/CGU16；公共 driver 及部分 std/泛型仍由 LLVM 编译。这是库后端差分，不是全程序 KFRC 替换。正式运行固定一个可用 CPU，编译保持 8 vCPU 与 8 个 codegen 线程。21 轮交替运行包含同一基线二进制的控制标签，计时不与编译或 profile 并发。配对比值与 bootstrap 区间仅描述本次实验内部波动。

七轮初筛保留为独立实验。W3 的 semver 全部 171 个函数字节、重定位、最终可执行文件都与基线相同，但初筛 requirement 计时仍相差约 2.7%；同一文件的双标签控制也出现波动，不能将此归因于 W3 代码或布局。humantime duration-format 五个函数的静态调用闭包及动态指令数同样未变。最终正式测量单独留存，不混池或静默替换初筛数据，也不据这些波动引入按函数名的布局特例。

验证包括 workspace、四库 corpus、13 项原 workload checksum，以及 enum、integer 和新增 private-integer-lanes 原生差分。新增 fixture 的 10,006 组输入包含整数字节序、符号截取、同对象部分覆盖前后的快照及相邻字节写入。指针原生用例实际生成 object 并链接 C 执行，覆盖调用修改 load 来源并覆盖 flags 的场景。

完整上游 unit suite 仍有既有未实现 intrinsic 的覆盖缺口；本轮不将四库 corpus 或 integration 通过表述为完整 upstream unit 通过。编译时间减半及全面追平 LLVM 仍是后续目标。
