# 持续测量的指标

目标：把“SoN 局部性差”从担心变成每次构建都有的数字，并与 [levels.md](../../design/ir/levels.md#风险v8-离开-son-的教训) 的风险表、[compile-time.md](../../design/goals/compile-time.md#指标与闸门) 的指标表接上。

## 指标表

| 指标 | 怎么测 | 参照 / 期望 | 采集层 |
|---|---|---|---|
| 字节/节点（按级别） | `FunctionGraph` 自报：`(nodes + 列 + 溢出池 + 常量池) / 存活节点` | 新布局约 26（不含 GVN）；现状 96（T1） | 计数器，每图 |
| 每节点堆分配次数 | 调试构建的计数分配器 | ≈0；现状 1.33（T1） | 计数器 |
| 存活率 | 存活节点 / 已分配 id | 低于 70% 触发压实（Graal 阈值） | 计数器，每压实点 |
| 每次改动的访问数 | 每个 pass 的 `visits / changes` | V8 SoN 约 20；InstCombine 83% 无改动 | 计数器，每 pass |
| 平均输入回指距离 | 序列化时对 `id − input` 取平均 | 越小越好；打乱后会变大 | 序列化时顺便算 |
| varint 字节/节点 | R 图 metadata 的字节 / 节点数 | 合成图 5.4–5.7（T4） | 每个已发布 R 图 |
| GVN 表字节/条目、命中率 | 表自报 | 19 B/条目（T3） | 计数器 |
| 驻留：本地缓存命中率、共享表访问次数、`try_lock` 失败次数 | 驻留器自报 | 本地命中率高于 90% 时共享表不成瓶颈（T6 场景 95%） | 计数器 |
| 驻留表条目数与字节 | 驻留器自报 | 对照 rustc 每类型 48 B 数据 | 构建结束 |
| L1d miss / 节点、L1d miss / 指令 | `perf stat -e L1-dcache-load-misses,instructions:u`，按阶段用 `--control` 或分进程 | V8：SoN 约为 CFG 的 3×，个别阶段 7× | E2B 上的正式测量 |
| 峰值 RSS 与并行增量 | `/usr/bin/time` / cgroup `memory.peak`；jobs=1 与 jobs=N 对比 | rustc 并行最多 +35%，Zig +28.1% | 每次正式基准 |
| 同时存活的图字节 | 调度器自报 | 不超过预算 | 计数器 |
| 内容哈希耗时占比 | 计时器 | 128 位 SipHash 约 6 ns/节点（T5），应远小于 1% | 计时器 |

【推断】计数器类指标进程内采集、成本低，所有 walkthrough 和测试都可以开；硬件计数器只在 E2B 的正式测量里采。macOS 上没有 `perf`，本机只能看计时和计数器（见 [bench-method.md](bench-method.md)）。

## 怎么测 L1d 才有意义

| 要点 | 理由 |
|---|---|
| 与同一输入的 rustc 阶段对比，而不是只看绝对值 | V8 的 3× 是 SoN 与 CFG 的相对值 |
| 按阶段分开：构建期窥孔、R 级 worklist、特化、L 级降低、placement、寄存器分配 | V8 的“个别阶段 7×”说明平均值会掩盖问题 |
| 同时记录 `instructions:u` | miss/指令 比 miss 总数更能说明布局问题 |
| 在 E2B 0820 环境、同一模板内对照 | 遵循既有 profile 规则：原版与候选同沙箱串行，不混用不同宿主机的绝对数 |
| 加一个“打乱存放顺序”的对照臂（调试开关在压实时随机重编号） | 直接量出创建顺序带来的局部性收益；T1 合成图上是 2.6–4.0× |

## 接入 levels.md 风险表的改法（建议）

| 风险行 | 现有指标 | 建议改为 |
|---|---|---|
| 局部性 | 每节点平均访问时间；placement 耗时占比 | 加“字节/节点（按级别）”“每节点堆分配次数”“存活率”“打乱顺序对照臂的减速比”；起点从 M2 提前到**迁移第 0 步**（现有图就能测） |
| 无效访问 | 每次改动对应的节点访问数 | 不变；按 pass 拆分，与 V8 的 20、InstCombine 的 83% 并列 |
| 缓存不命中 | L1d miss | 改为“L1d miss/指令，按阶段”，在 E2B 采集；附 rustc 同场景对照 |
| （新增）内存 | — | “峰值 RSS 与并行增量”“同时存活的图字节”，参照 rustc +35%、Zig +28.1% |
| （新增）驻留 | — | “本地缓存命中率”“共享表访问/锁失败次数” |

判定规则（【推断】，供 T38 评估混合方案时使用）：

1. 若紧凑布局下 L1d miss/指令 仍比同输入 rustc 的 MIR 优化 + LLVM 中端高 2 倍以上，且 placement 占 L 级耗时超过 20%，在 T38 内试“L 级 CFG”臂。
2. 若字节/节点或分配次数回退到契约草案水平（>60 B 或 >0.1 次），视为回归，先修存储而不是换 IR。
