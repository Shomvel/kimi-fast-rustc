# Architecture

`kfrc` is a native-only compiler and never links to or invokes LLVM. It does not use Cranelift. Legacy LLVM modules and benchmark records are archival evidence only, not an active compiler path or fallback.

## Native backend path (no LLVM)

The native backend uses a sea-of-nodes graph: nodes represent computations and edges represent data or control dependencies. Nodes do not inherently have an execution order. Optimization rewrites the graph, then an explicit block-placement pass puts control flow into basic blocks. Control-flow graphs also run value numbering, constant folding, and algebraic simplification, but only on pure data nodes: rewrites mutate nodes in place to preserve SSA order, trapping operations are retained, and control edges are unchanged. Value-numbering tables reset at every function `Start`, preventing representatives from crossing function boundaries. When every use of a comparison is an `If` condition, lowering replaces the comparison with a no-op, compares its original operands, and jumps to the false arm using the inverse signed or unsigned condition. Shared comparisons and ordinary boolean expressions still use `setcc` and zero extension. Strength reduction rewrites multiplication by a power of two into `shl` on either operand side and unsigned division by a power of two into `shr`; signed division keeps its rounding semantics. These rewrites run in both optimization paths and mutate existing nodes without scheduling. A use replacement counts as progress only when it changes at least one use, guaranteeing fixed-point convergence. Conservative dead-code elimination then roots all control nodes, calls, and potentially trapping divisions while removing unused pure computations. This pass does not perform ILP scheduling or reorder instructions within a block. Instruction selection preserves lowering order and relies on CPU out-of-order execution for dynamic scheduling. Immediate loads use sign-extended `C7 /0 imm32` whenever the value fits `i32`, reducing those encodings from 10 to 7 bytes; larger values retain `B8+rd imm64` (`movabs`). Right-hand constants are preserved as `Operand::Imm(i32)` when possible, using `81` group arithmetic/bitwise/compare encodings and `69` immediate multiplication. Constant nodes used only by those right-hand operands become no-ops; large constants and left-hand uses still materialize in registers. Addition, multiplication, and bitwise commutative operations normalize a left constant into that right-hand immediate position only when the other operand is not constant, avoiding invalid no-ops when both sides need evaluation. Immediate division is rejected because x86 has no such instruction. Linear-scan register allocation maps virtual registers to target registers and inserts spills. The emitter suppresses moves whose source and destination physical registers are identical, while preserving spill loads and real moves. Outgoing stack arguments encode ModRM plus the required `0x24` SIB byte for `[rsp+disp32]`. The initial native target is x86_64 System V on Linux, with no LLVM libraries, tools, or subprocesses in this path.

The native backend must never silently change Rust semantics. Unsupported Rust constructs are rejected explicitly while the backend is experimental; there is no fallback compiler path. The frontend tracks `i64`, `u64`, and `bool` types in bindings, expressions, and function signatures. Unsigned literals can be inferred from unsuffixed literals in a `u64` context, but concrete signed and unsigned variables cannot be mixed without an explicit `as` cast. Casts between `i64` and `u64` preserve the bit pattern, `bool` casts to integers produce zero or one, and numeric-to-`bool` casts are rejected. These casts only change frontend type information and emit no instruction. Conditions require `bool`; logical `&&` and `||` place the right expression on the required control path and merge it with a constant on the other path. Correctness tests compare native execution with the source-level expected result before performance claims are made. Mutable locals are versioned as SSA values. Every reachable `if` arm ends in an explicit `Jump` to its merge region, so nested statements do not depend on physical branch layout. A `while` header accepts its entry and any number of back edges from ordinary completion and `continue`. Each `break` records an exit jump with the current SSA values; a loop with breaks merges those edges with the normal condition exit. Numeric `for start..end` and `for start..=end` loops evaluate both endpoints once, create the comparison after the loop-header Phi exists, and expose a read-only per-iteration binding. Hidden induction names are unique per nesting depth, and ordinary back edges increment the induction variable. Inclusive ranges emit a final-iteration guard that exits instead of overflowing; `continue` uses the same guard before either incrementing or exiting. `usize` is an alias of `u64`. Phi self-moves are discarded. Acyclic Phi copies are emitted directly without temporary registers; when a destination occurs in another copy's source, temporaries still preserve parallel-copy semantics for the cycle. Live ranges that cross a loop header extend through its back edges. Unconditional `loop` statements use the same header and exit machinery with a constant-true condition. A function-tail expression is parsed only when no semicolon follows, produces a typed `Return`, and is distinguished from statement keywords and the independent `return` token. Functions may contain multiple `Return` nodes; instruction selection emits each return and its register restoration, while the last return delimits each function graph for multi-function compilation. Single-function lowering explicitly rejects multiple `Start` nodes. Integer bitwise operations use the ordinary two-address binary path. Shifts preserve the left input in scratch. Variable counts load `cl`, while constant counts use `C1 /4|5|7 imm8` with the same six-bit mask, avoiding constant moves into `rcx`. Both forms use `shl`, arithmetic `sar`, or logical `shr`. Unsigned division clears `rdx` and uses `div`, while signed division uses `cqo` and `idiv`; direct object emission encodes the same operations without an assembler. The encoder records label offsets and jump fixups, then resolves local `rel32` displacements relative to the next instruction, rejecting duplicate or unknown labels and overflow. External calls still use ELF `R_X86_64_PLT32` relocations.

## Constraints

- No Cranelift.
- No disabling optimization to make compilation appear faster.
- No unsafe floating-point reassociation by default.
- `target-cpu=native` results are reported separately from portable results.
- Binary size and runtime are both first-class metrics.
- All official builds and benchmarks run on SSH host `yicloud-dev`.
- Modules use only the Rust standard library unless the root manifest is deliberately changed by the integrator.
