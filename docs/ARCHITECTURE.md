# Architecture

`kfrc` is a native-only compiler and never links to or invokes LLVM. It does not use Cranelift. Legacy LLVM modules and benchmark records are archival evidence only, not an active compiler path or fallback.

## Native backend path (no LLVM)

The native backend uses a sea-of-nodes graph: nodes represent computations and edges represent data or control dependencies. Nodes do not inherently have an execution order. Optimization rewrites the graph, then an explicit block-placement pass puts control flow into basic blocks. Control-flow graphs also run value numbering, constant folding, and algebraic simplification, but only on pure data nodes: rewrites mutate nodes in place to preserve SSA order, trapping operations are retained, and control edges are unchanged. Value-numbering tables reset at every function `Start`, preventing representatives from crossing function boundaries. Each nonempty pass batches replacements into one control/data/memory scan, resolving subsequent expression keys through the pending map instead of rescanning the whole graph per merge. Immediate-dominator chains computed from reverse postorder guard reuse with O(V) dominator storage: non-constant, non-parameter expressions merge only within one block or when the representative's block dominates the candidate, preventing loop-body and branch-local values from replacing exit or post-merge computations. When every use of a comparison is an `If` condition, lowering replaces the comparison with a no-op, compares its original operands, and jumps to the false arm using the inverse signed or unsigned condition. Nested comparisons against boolean constants simplify to the original or inverse comparison in place: `(a < b) == true` reuses `a < b`, while `!(a < b)` becomes `a >= b`, including unsigned counterparts. A constant on the left is swapped into the right-hand immediate position using the inverse relational operator when the other operand is non-constant. Shared comparisons and ordinary boolean expressions still use `setcc` and zero extension. Comparisons against immediate zero emit `test reg, reg` on both boolean-result and direct-branch paths, while the reference evaluator retains `(reg, 0)` comparison state for every signed and unsigned condition. Strength reduction rewrites multiplication by a power of two into `shl` on either operand side, unsigned division into `shr`, and unsigned remainder into a bitmask, including the `2^63` case; signed division by a positive power of two adds a sign-derived bias before an arithmetic shift to preserve rounding toward zero; signed remainder and other divisors retain their original trapping semantics. Replacement shift/mask constants are newly allocated so shared source constants retain their values. In-place algebraic rules also rewrite `0 - x` and multiplication by `-1` into wrapping negation, and XOR with all ones into bitwise inversion, for either constant operand position. These rewrites run in both optimization paths without scheduling. A use replacement counts as progress only when it changes at least one use, guaranteeing fixed-point convergence. Conservative dead-code elimination then roots all control nodes, calls, and potentially trapping divisions while removing unused pure computations. A restricted LICM handles natural loops with a unique preheader: only pure non-division expressions whose operands are independent of the loop Phi and dominate that preheader are hoisted, with stable node/metadata remapping and no ILP scheduling. This pass does not perform ILP scheduling or reorder instructions within a block. Independent functions compile in bounded workers that dynamically claim declaration indices with an atomic counter; result and error order remains declarative and object emission is deterministic. The native-batch pipeline uses typed bounded synchronous channels with configurable bounded workers per stage. Stable input indices drive contiguous-prefix output reordering while preserving backpressure, cancellation, and indexed errors without type-erased stage values. Each batch input emits one program object containing all declared functions and their call relocations; single-function inputs retain the legacy filename-stem symbol path. Instruction selection preserves lowering order and relies on CPU out-of-order execution for dynamic scheduling. Immediate loads use sign-extended `C7 /0 imm32` whenever the value fits `i32`, reducing those encodings from 10 to 7 bytes; values in `0x80000000..=0xffffffff` use zero-extending `B8+rd imm32` (5 bytes, plus REX.B for extended registers), and only larger bit patterns retain `B8+rd imm64` (`movabs`). Zero immediates use `xor reg, reg` only when flags are not live from a preceding compare/test to its conditional use; conservative label, call, and return boundaries retain `mov`. Right-hand constants are preserved as `Operand::Imm(i32)` when possible. Values fitting signed imm8 use `83` group arithmetic/bitwise/compare encodings and `6B` immediate multiplication; larger values retain `81` and `69`. The stack-frame subtraction uses the same imm8 rule. Constant nodes used only by those right-hand operands become no-ops; large constants and left-hand uses still materialize in registers. Addition, multiplication, and bitwise commutative operations normalize a left constant into that right-hand immediate position only when the other operand is not constant, avoiding invalid no-ops when both sides need evaluation. Immediate division is rejected because x86 has no such instruction. Linear-scan register allocation maps virtual registers to target registers and inserts spills. Spill expirations are ordered by interval end and slot, avoiding a scan of all historical spills for every new interval. Move hints transfer a source register only at the destination's first definition when the source dies at that move, the source still owns a register, and no other interval starts there; fixed destinations and all other cases retain ordinary allocation. The emitter suppresses moves whose source and destination physical registers are identical, while preserving spill loads and real moves. RBP/RSP memory operands use disp8 for offsets fitting `-128..=127`, omit displacement entirely for `[rsp]`, and retain disp32 otherwise; RSP addressing always keeps the required `0x24` SIB byte. The initial native target is x86_64 System V on Linux, with no LLVM libraries, tools, or subprocesses in this path.

The native backend must never silently change Rust semantics. Unsupported Rust constructs are rejected explicitly while the backend is experimental; there is no fallback compiler path. The frontend tracks `i64` (`isize` on x86_64), `u64` (`usize`), and `bool` types in bindings, expressions, and function signatures. A signature pre-scan skips balanced function bodies, records declaration-order symbol indices, and then parses bodies, so forward calls, self-recursion, and mutual recursion use checked signatures and correct `Call` targets. Top-level `pub`, `pub(crate)`, `pub(self)`, and `pub(super)` visibility is consumed without changing those symbols. `const fn` accepts the same visibility combinations and reuses ordinary runtime calls; it does not yet provide compile-time evaluation. Top-level scalar constants accept typed constant expressions with arithmetic, bitwise operations, shifts, comparisons, boolean short-circuiting, parentheses, and references to other constants. Initializers are evaluated at compile time with dependency ordering and cycle detection; division by zero, signed overflow, and invalid shifts are diagnosed instead of becoming runtime code. Each reference emits a typed constant and shares the top-level namespace with functions; calls in initializers remain unsupported. Function subgraphs retain transitive dependencies appended by later optimization passes; construction scans only the current contiguous range and required external dependencies, then rebuilds after `Start` with remapped inputs and metadata instead of dropping or forward-referencing constants. Program cache keys cover the complete graph, declaration order, call targets, target/ABI, backend version, and single- versus multi-function object format; entries are written only after successful object emission. Multi-function keys are computed in deterministic 256-slot shards with jobs-independent outer hashing; cache reads use one file open and type-specific decoding, avoiding a second ELF scan on hits. Decimal, binary, octal, and hexadecimal literals accept underscores and the supported integer suffixes. Unsuffixed literals retain their full 64-bit magnitude until their type context is known; a `u64` context accepts the entire range, while signed use rejects magnitudes above `i64::MAX`. Concrete signed and unsigned variables cannot be mixed without an explicit `as` cast. Compound assignments cover arithmetic, bitwise AND/OR/XOR, and both shift directions. Casts between `i64` and `u64` preserve the bit pattern, `bool` casts to integers produce zero or one, and numeric-to-`bool` casts are rejected. These casts only change frontend type information and emit no instruction. Unit-returning calls produce an internal `()` type, which may be discarded, bound, or returned from a unit function but cannot enter numeric operations, casts, or typed results. Statements accept either assignments or semicolon-terminated expressions, including unit/non-unit calls and discarded pure expressions. Unary `!` keeps logical negation for `bool` and lowers signed or unsigned integer operands to the shared `UnaryOp::Not` bitwise-complement path; unit operands are rejected. Conditions require `bool`; logical `&&` and `||` place the right expression on the required control path and merge it with a constant on the other path. Scalar `match` supports typed integer/boolean literals, inclusive ranges, and boolean arm guards with a required final unguarded wildcard. Range overlap and reversed endpoints are diagnosed, and guard evaluation only occurs after its pattern succeeds, using the same nested control regions and result Phis. Correctness tests compare native execution with the source-level expected result before performance claims are made. Mutable locals are versioned as SSA values. `let` shadowing parses the right-hand side before replacing the binding, preserves independent type/mutability, and uses a shadow stack so branch Phis, loop back edges, `break` snapshots, and `for` bodies do not leak inner bindings. Every reachable `if` arm ends in an explicit `Jump` to its merge region, so nested statements do not depend on physical branch layout. A `while` header accepts its entry and any number of back edges from ordinary completion and `continue`. Each `break` records an exit jump with the current SSA values; a loop with breaks merges those edges with the normal condition exit. Numeric `for start..end` and `for start..=end` loops evaluate both endpoints once, create the comparison after the loop-header Phi exists, and expose a read-only per-iteration binding. Hidden induction names are unique per nesting depth, and ordinary back edges increment the induction variable. Inclusive ranges emit a final-iteration guard that exits instead of overflowing; `continue` uses the same guard before either incrementing or exiting. `usize` is an alias of `u64`. Phi self-moves are discarded. Acyclic Phi copies are emitted directly without temporary registers; when a destination occurs in another copy's source, temporaries still preserve parallel-copy semantics for the cycle. Live ranges that cross a loop header extend through its back edges. Unconditional `loop` statements use the same header and exit machinery with a constant-true condition. A function-tail expression is parsed only when no semicolon follows, produces a typed `Return`, and is distinguished from statement keywords and the independent `return` token. Functions may contain multiple `Return` nodes; instruction selection emits each return and its register restoration, while the last return delimits each function graph for multi-function compilation. Single-function lowering explicitly rejects multiple `Start` nodes. Integer bitwise operations use the ordinary two-address binary path. Shifts preserve the left input in scratch. Variable counts load `cl`, while constant counts use `C1 /4|5|7 imm8` with the same six-bit mask, avoiding constant moves into `rcx`. Both forms use `shl`, arithmetic `sar`, or logical `shr`. Unsigned division clears `rdx` and uses `div`, while signed division without an eligible positive power-of-two divisor uses `cqo` and `idiv`; direct object emission encodes the same operations without an assembler. The encoder iteratively shortens eligible local branches to `EB rel8` or `7x rel8`; out-of-range branches retain `E9`/`0F 8x rel32`. During shortening, prefix deltas describe the current layout without rewriting every offset. Non-overlapping ranges are then compacted once with `copy_within`, and labels, fixups, and PLT32 call offsets are remapped only on the final layout. Final displacements are computed relative to the next instruction, rejecting duplicate or unknown labels and overflow. External calls still use ELF `R_X86_64_PLT32` relocations.

## Constraints

- No Cranelift.
- No disabling optimization to make compilation appear faster.
- No unsafe floating-point reassociation by default.
- `target-cpu=native` results are reported separately from portable results.
- Binary size and runtime are both first-class metrics.
- All official builds and benchmarks run on SSH host `yicloud-dev`.
- Modules use only the Rust standard library unless the root manifest is deliberately changed by the integrator.
