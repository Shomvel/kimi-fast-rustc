# Crate 级程序库与发射归属

本轮落实 Fable 审查 A1 的归属模型：CGU 决定目标文件的放置，不限制优化器看见的函数与常量。
每个单态函数有一份可发布的 S 图；准备完的图同时供调用方定价、内联和自身机器编译使用。

## 收集与共享

rustc 转换期间仍用函数名和 allocation ID 临时命名常量。CGU 清单齐备后，
`CrateGraphs::lift_data` 把函数、静态量和机器适配器收集的数据移入同一 `ProgramData`。
所有函数图共享该池的不可变 `Arc`，图中保存符号引用，不在拼接时复制常量字节。
内存分区的只读证明、验证器与解释器通过同一查询读取定义。

只有本地、只读、`unnamed_address`、非 TLS 对象可按内容合并。
内容包含字节、对齐和每条重定位的偏移、目标与 addend。先规范化依赖，再规范化引用者，
因此指向相同字节的两份嵌套常量也能合并。哈希提供稳定名字，完整对象比较决定是否可合并；
哈希碰撞产生不同名字。依赖环保留原有名字与重定位，不递归展开，当前不对同构匿名环做内容去重。

具名静态量、可写量与 TLS 保留身份。它们的 owner 为 rustc 放置 CGU 中序号最小者。
带名字的静态定义是根；匿名数据仅由存活代码和数据重定位保活。
局部布局降低新建的常量在机器编译后加入同一池，并重写最终机器重定位。

## 函数可见性与唯一编译

`CrateProvider` 向优化器暴露整个 crate，只有 `no_inline` 等语义策略限制内联。
CGSCC 发布的图就是后续调用方与发射使用的图，不再保留仅某些 CGU 可用的第二份发射候选。
普通调用点仍受现有成本与工作预算控制；本轮不以增加阈值获得收益。

发射对机器码与数据重定位求闭包。每个存活函数只编译一次，进入 rustc 原有放置中序号最小的 CGU。
被另一 CGU 引用的本地函数以全局绑定、隐藏可见性发射。其他 CGU 仅引用这个定义。
公开定义保持公开，未被引用的内部函数省略。

匿名常量在每个实际使用它的 CGU 各放一份本地定义，同一 CGU 相同内容只有一份。
具名/可写/TLS 数据只在 owner 发射；跨 CGU 引用也提升为隐藏全局符号。
此步骤只改变符号绑定和重定位目标，不修改已编码的指令字节。

## 独立图与边界

`kfrc-son` 也接受没有 shell 的独立输入图，因此保留 `data_objects` 作为独立输入和局部降低的新数据。
独立图内联仍要检查数据身份与 provider 的可引用契约。真实 rustc 流水线在内联前已把这些定义提升进 crate 池，
常量导入预算和私有 CGU 可见性不再限制这条路径。不同 crate 池不能作为同一个程序直接拼接。

不返回函数的拼接与属性消费另见 [noreturn.md](noreturn.md)。R 级内联和 R/S/L 共用的稀疏优化器
仍是 A2/A4 的后续边界，不能由唯一属主或 Cranelift 替代。

## 验证

`crates/rustc_codegen_kfrc/tests/program-data/run.sh` 经真实 rustc 构建三个 rlib 再用 LLVM 驱动链接，
对照 LLVM、单 CGU 与十六 CGU 的输出和静态量最终状态，并记录 ELF 唯一定义、隐藏符号及常量。
语义前端目前明确拒绝 TLS；其运行时验证由独立 frontier probe 记录，不能计入通过项。
四库门禁另检查真实数据的 `data_conflict`、`private_reference`、函数副本、只读数据量、
执行指令、代码体积与编译指令。测试和测量结果单独记录，不以架构描述作为验收证据。
