# 约束、抽象状态与真实效果的契约

设计修订：2026-11-09。本文补充 [语义要求与事实](requirements-and-facts.md)，检查那些
没有普通数值结果、或者主要约束优化的 IR 概念。均为目标契约，不表示相应功能已经
实现。实现覆盖和历史测量仍以 [PoC 状态](../../plan/poc/semantic-ir-status.md) 为准。

## 不是所有约束都应该成为可执行节点

每项机制必须明确：源语义依据、输入与输出、抽象状态变化、违反时的错误类别、
作用范围与失效条件，以及最终的擦除或机器实现。只有“阻止优化”“保留语义”
或“固定在控制上”的说明不构成完整契约。

| 类别 | 代表 | 运行时地位 |
|---|---|---|
| UB 要求 | RequireDefined、RequireValid、Assume | 有语义执行位置，不要求发布代码执行检查 |
| 证明记录 | VariantWitness、范围、对齐及访问凭据 | 非执行数据；约束实际消费者 |
| 内存版本依赖 | Effect(P)、MemMerge、效果 Phi | 表示状态和排序，不是数据搬运或硬件屏障 |
| 抽象状态转换 | SlotLive/SlotDead、借用作用域 | 改变合法访问／初始化或可用凭据；无须逐一对应机器指令 |
| 分析保守化 | Escape、失效的 Local 标签 | 编译器知识变弱，不是程序主动执行一种“逃逸效果” |
| 优化策略 | Opaque/black_box、cold、likely/unlikely | 按特定策略约束优化，不能提供 UB 假设或访问许可 |
| 真实行为 | Check、Drop、Call、Atomic、Volatile、Fence、Terminate | 保持各自可观察行为；不能统一擦除 |
| 编译期待答问题 | Hole、布局与 trait 解析请求 | 类型／编译依赖，不是运行时检查或效果 |

“最终不发指令”不能推出“可以现在随便删除”；“在效果链上”也不能推出“读写所有内存”。

## 本轮核对发现

下表记录此次只读源码核对与文档修订，不是生产修复回执；实现仍需单独迁移和验收。

| 原有表述或实现现象 | 修订决定 |
|---|---|
| ObserveValue 解释器以 contains_poison 判断，布局却展开整树；机器层仅取值／搬运 | 明确 poison 要求，分离证明与执行需求，不以整体类型有效性之名掩盖覆盖缺口 |
| Refine 兼有 Variant、Assumed、ControlOnly，旧表写 Proven 可投机 | 拆要求、凭据、访问条件与放置依赖；所有来源都受作用域约束 |

| 文档称 MemMerge 合并 token，又说逃逸把不同分区放进一个 Phi | 区分同点打包、同分区前驱选择和依赖重建 |
| 文档把 loop 无 break 列为 Unreachable | 发散 CFG、无返回调用和到达即 UB 分开；当前解释器 Unreachable 结果的分类也须核对 |
| Opaque 被描述为 preserves value and effects，实际用于 black_box 和求值保留 | 明确恒等结果、优化策略、输入求值与内存效果，不能兼任通用语义屏障 |
| 文档要求资源恰好消费一次，或 EndBorrow 后不能用地址 | 验证源义务及 scope 凭据，允许合法 forget／泄漏及其他权限下的地址使用 |
| NonNull 被列为天然对齐，Frozen/Const load 被称为只依赖指针 | 缩小到有依据的事实，访问许可、范围和寿命另证 |
| 文档仅由 -> ! 推断冷路径 | 冷是策略，不是不返回类型的语义结论 |

## 内存版本、打包与合流

`Effect(P)` 表示某次执行中分区 P 的状态及依赖，不是内存内容的复制。为读操作
保留的顺序依赖不证明发生写入，也不证明其他分区与 P 不相交；独立调度必须先有
分区不相交或兼容访问的证据。多个分区标签挂在单条效果链上，不等于已经实现多链。

三个容易混淆的操作分别定义：

- `MemMerge` 是同一控制位置上各分区当前 token 的稀疏映射，保持默认分区和精确
  分区覆盖。不选择路径，不 join 线程，不产生 fence，不产生机器拷贝。
- `Phi<Effect(P)>` 在 Region 按实际前驱选择同一个 P 的版本；不同分区的 token
  不能随意塞进同一个 Phi。“有 Phi”本身不证明状态一致。
- 精确分区并回 Unknown 是分析及依赖重建：后续 Unknown 访问依赖原 Unknown
  与该精确分区的相关版本；在控制合流处逐前驱规范成同一分区视图，再做 Phi。
  不需要发明硬件 merge 操作。

verifier 检查版本覆盖、前驱对应、互斥分支及每条可执行路径上的顺序。
发布代码消去 token 表示之前，实际读写、调用、原子和 fence 的依赖必须已落实。

## 分区资格与逃逸

Local、Heap、Const 的资格来自分析或已验证的生产者事实；Frozen、Unique 的
资格还依赖明确的源语言参数／protector 契约。两者都不是仅凭类型名或标记就成立。
源程序违反已确认的语言契约才是源 UB；编译器凭据缺失、越界使用或错误推断分区
一律是编译器错误，不能归罪于用户。

`Escape` 仅表示从某个控制点开始，未知代码可能通过其他路径访问原分区。
实际 store、调用或指针暴露操作已经表达其程序行为；Escape 不重复执行它们，
也不自行令指针失效、结束借用或产生 UB。保守地多判逃逸会损失优化，少判逃逸
可能错编译。不能仅因没有显式 Escape 标记就认定不逃逸。

内联、memcpy/memmove 降低或其他引入调用的变换之后，旧 Local 标签必须重新验证
或失效；不能按库函数名字默认 no-capture。对只读分区，也须区分内容不变、分配
存活、访问范围与对齐：Const/Frozen 不自动允许任意偏移的 load 或任意投机。

## Reborrow 与 EndBorrow

这里的作用域用于保留被内联调用确有的 protector／别名契约，不自动覆盖所有
源语言局部重借用。拆清两件事：建立依赖源契约的访问凭据，以及可选地分出效果链。
即使复用父分区而不创建子链，契约的作用域也不能随之丢失。

`Reborrow` 输入是原地址／范围、父内存视图及契约依据；输出是作用域身份、访问
凭据，以及需要时的子分区视图。它不分配、初始化或复制对象，不凭空创造 provenance。
`EndBorrow` 结束这些临时凭据，并把子链依赖及逃逸状态交回父视图；不写回对象，
不自动 drop，也不让底层地址仅因该标记而失效。

正常和 unwind 出口上都要关闭有限的作用域；真正不返回的路径无需伪造出口。
结束后不能再使用该 scope 的权限或分区事实，但仍可按其他有效凭据使用同一底层
地址。返回的引用是否可用由源借用／provenance 契约决定，不由 EndBorrow 名称决定。
错误的 scope 配对是 IR 错误，不是用户 UB。

## 存储寿命、初始化、move 与 drop

`StackSlot` / 实现中的 `LocalSlot` 标识存储对象；`SlotLive` 开始一次动态存储寿命，
`SlotDead` 结束它。新寿命初始内容未初始化，但这不要求生成清零；结束寿命也不
执行析构。循环中同一 slot 地址的下一次 SlotLive 是另一动态寿命，旧访问凭据不能
仅凭地址相同复用。

move 改变的是源位置的初始化和所有权状态，不自动结束整个槽的存储寿命。
部分 move 尤其不能杀死其余字段。普通赋值可在同一寿命中重新初始化；StorageDead
才可产生 SlotDead。优化器删除寿命标记前必须完成逃逸、访问安全及栈槽复用分析，
并将依赖移交给实际访问；不能把它们当成无条件可删的调试注释。

drop 是真实代码，可能修改内存、调用外部函数或 unwind。所有权验证跟踪的是
Body 指定的义务是否正确转移、执行或按源操作解除，不强制每个拥有资源的值最后
都析构：`mem::forget`、`ManuallyDrop` 和合法泄漏不能被改成 UB 或强制补 drop。
SSA 值因 Copy 有多个使用者也不等于违反线性消费。返回、转移、unwind、终止及
不返回路径分别处理，不能只检查 NodeId 使用次数。

## Unreachable、发散与终止

| 形状 | 精确含义 |
|---|---|
| `Unreachable` | 若执行到这里，源契约给出 UB；是无后继终结点，不是“普通不返回” |
| CFG 循环 | 表示实际循环；不能仅因没有返回就改成 Unreachable |
| 已证明不正常返回的调用 | 保留调用效果及适用的 unwind／终止行为；不可能的正常延续可接 Unreachable |
| `Terminate` / abort | 真实异常终止；不是可任意擦除的 UB 声明 |
| 从 Start 无法到达的块 | CFG 分析结果，可删除；不等于所有包含 Unreachable 的前缀都不可达 |

源语言对特定无效果循环的前进保证另行证明；`may_diverge` 也不能当成“必然 UB”
或“必然不返回”。Unreachable 的源语义出处和消除前缀效果的合法性必须可追溯。
解释器把 reached-unreachable 与正常返回、panic、发散及超预算分别分类。

## Opaque 与其他优化策略

生产实现中的 Opaque 用于 black_box 等优化边界。目标契约是值恒等、按约定限制
编译器利用输入的已知性质，不是 RequireDefined，不提供有效性证明，也不是
隐含的外部函数调用或通用内存屏障。

输入的必要计算、源操作自带的有效性要求与既有副作用分别保留。black_box 的
可接受优化限制及其后端实现需要单独声明；它是 best-effort 优化提示，不提供
安全或常数时间保证。不得先当普通恒等式折叠，再声称已保留优化屏障。
首版策略至少阻止利用屏障输入的已知常量／范围直接替换其输出，阻止 GVN 以
普通纯恒等式跨过该边界；解释器仍返回同一值，不随机改值。它不禁止屏障两侧
各自合法的局部优化，也不新增“值已有效”的事实。仅为保留求值而使用 Opaque 的
producer 路径应改按其真实效果／语义要求表达，不额外继承 black_box 的策略。
若需要保护指定可达内存不被优化，必须声明相应效果和后端机制，不能仅用
“preserves effects”暗示任意内存行为。

cold、likely/unlikely、inline 提示是策略输入，不是可达性、终止性或有效性证明。
`-> !` 也可能是程序热循环，不能仅凭不返回类型推断低频。冷分支仍然必须正确，
不能改变 panic、unwind 和真实调用行为。

## 真实排序和编译期问题

Atomic、Volatile、Fence 具有各自的语言及目标机语义。Release fence 的 token
输入可约束先前写入而不把 fence 伪装成读操作；该排序也不能因“没有结果值”而
删除。编译器屏障与线程同步屏障分开，不能用 Opaque 替代硬件所需的排序。
多线程正确性需 litmus 等验证，单线程解释器相等不能证明。

Hole 的问题和答案是编译依赖：未知不等于 false，不是 UB，也不能退化成猜测的
运行时值。被不可达分支独占的问题可以按特化契约跳过；mentioned items 所要求
的编译期诊断仍独立执行。布局相同不意味着类型有效性、drop 或调用目标相同。

## 审查准入与迁移验收

新的约束概念必须先归类，给出完整契约；能用已有的操作契约、证明记录或分析
结果表达时，不再增加万能 Marker/Barrier/Refine 节点。GraphState::Verified 只是
某一图版本经过检查的状态，不是持久证明；相关图或事实改变必须使验证和分析失效。

必须补充的验收形状包括：分区打包误当跨分支合流、布局引入调用后 Local 失效、
只读但越界的 load、EndBorrow 后复用过期凭据、部分 move 后继续用其他字段、
SlotLive 新一轮复用旧地址、合法 forget、有限循环／不返回调用／UB 的区分、
Opaque 结果值与优化策略，以及 fence 不被误当作读或空操作。
仅修改文档不算实现这些测试；现有冻结指标不变。
