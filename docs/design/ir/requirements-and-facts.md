# 语义要求、事实与放置约束

设计修订：2026-11-09。本文规定 `ObserveValue` / 通用 `Refine` 的目标替代契约，
不表示生产代码已经迁移。当前实现与验收仍以 [semantic-ir-status.md](../../plan/poc/semantic-ir-status.md)
及冻结候选回执为准。旧 walkthrough 中的 `Refine` 示意按本文解释，历史测量不回写。
R/S/L 仍是同一个 `FunctionGraph` 的阶段，不新增另一套生产 IR。
Effect／MemMerge、借用与存储寿命、Escape、Opaque、Unreachable 及策略提示的
相邻契约见 [constraints-and-effects.md](constraints-and-effects.md)。

## 需要分开的概念

| 概念 | 问题 | 归属 |
|---|---|---|
| 内存初始化状态 | 哪些字节已写入，哪些仍未初始化？ | 抽象内存及表示快照 |
| Rust 类型有效性 | 内容能否在指定源语言操作处作为 `T` 出现？ | 类型规则、值产生和使用操作的契约 |
| IR poison | 中间计算是否产生不能在要求 defined 的位置使用的结果？ | IR 值域；不是一种机器字节 |
| 语义要求 | 执行到此处必须满足什么，否则源程序 UB？ | 有执行位置的 `RequireDefined`、`RequireValid`、`Assume` |
| 已知事实 | 在哪里可使用哪条性质，其依据是什么？ | 谓词、凭据及作用域 |
| 运行时检查 | 条件失败时程序实际做什么？ | `Check`、分支、panic 或错误返回 |
| 放置约束 | 哪个实际操作必须留在哪个控制或效果范围？ | 操作的控制、效果及证明依赖 |

字节 `2` 已初始化，但不能作为合法 `bool`；`MaybeUninit<bool>` 可以保存它，
转换为 `bool` 时才涉及相应的类型有效性要求。padding 和非活动 enum payload
不要求全部初始化。引用有效性、具体内存访问的许可和别名规则各有契约，
不能统一成递归扫描值及其指向的所有内存。

部分初始化的局部或快照是 IR 的中间状态，不因此成为一个合法的 Rust `T` 值。
Body producer 必须逐项登记构造、类型化读取、转换、传参和返回的源语义，
不能把调用边界当作唯一有效性边界；尚未建模的类型规则不能从 `contains_poison`
推断为已验证。

## 语义要求

| 操作 | 契约 | 结果和代码 |
|---|---|---|
| `RequireDefined(v)` | 到达此处时 `v` 的语义组成中没有 poison；只看活动 payload，遵守 `MaybeUninit` 契约 | 延续控制，无新业务值、无内存读写、无发布机器码检查 |
| `RequireValid<T>(v)` | 到达此处时满足 producer 指定且已建模的 `T` 有效性契约，包括其必要的 definedness | 同上；不能用单纯 poison 检查冒充完整实现 |
| `Assume(p)` | 到达此处时布尔谓词 `p` 必须 defined 且为真，否则 UB | 同上；之后可建立有作用域的假设事实 |
| `Check(p)` | 按操作定义进入成功或失败控制，失败有明确的 panic、返回等行为 | 真实运行时控制流；不得按 `Assume` 擦除 |

要求的输入引用原 SSA 值，不产出“认证后的另一份值”。解释器执行要求时进行
语义判断；发布机器码不因此扫描聚合或生成失败分支。调用、返回和类型化操作
优先携带自身的契约；内联删除操作边界时，按需留下独立要求，不对所有实参
无条件重复插入整值观察。

要求有执行位置，不是可随意上提的纯谓词：把仅在一条路径执行的要求移到
另一条本来有定义的路径上可能引入 UB。迁移初期可以复用已有控制／效果链
保持顺序，但效果 token 仅用于保守排序，不意味着要求读取或写入程序内存。
在保持诊断相等的模式下，未证明冗余的要求仍保留；按 refinement 擦除需经过
下文规定的阶段边界。

## 事实按用途区分

### enum 变体凭据

```text
n10 = VariantSwitch(opt)
some_block:                           // n10 的 Some 出口
  w1 = VariantWitness(opt, Some, n10.Some)
  x  = VariantField[Some, 0](opt) proof=w1
```

`VariantWitness` 是编译期证明记录，不是 `ValueTy::Rust` 或机器值，不要求作为
可执行节点存储。`MakeVariant(Some, x)` 自身可提供凭据；合法的 `Assume` 也可以
提供有条件的凭据。凭据必须匹配同一个 enum 值、同一个变体及其动态执行实例。
父 enum 的变体事实不能用于其嵌套 enum。

纯 `VariantField` 保留“变体不符则 poison”的全函数语义。凭据用于证明当前访问
匹配变体、消除选择或合法降低成物理访问；没有凭据时，降低不能随意读取非活动
payload 或把 poison 选择改成无条件 load。变体凭据本身也不证明底层地址可访问。

### 标量事实

范围、相等、非空、`i < len` 等登记为带作用域的谓词，供消费者查询或显式引用。
它们不改变原值身份，不要求每个使用者接一个新 `Refine`，不分配虚拟寄存器。
`p != null` 不证明可解引用、对齐、分配存活或 provenance；指针相等仍不能作为
替换另一个指针的充分依据。

### definedness 与类型有效性事实

这是语义要求、操作契约或构造器推导出的分析结果，与承载要求的操作分开。
例如在遵守已声明契约的调用正常返回后，可获得其返回值的 definedness。
`PassMode::Ignore` 只描述 ABI 运输，不提供这样的证明。

### 内存访问条件

对齐、分配存活、可访问范围和相应权限与具体操作关联。依赖内存的条件还需要
相关内存状态、生命周期或借用作用域；不能仅凭指针 SSA 身份永久复用。
在 `free(p)`、`SlotDead` 或相关写入之后，旧凭据按其依赖失效。
不把每个写入都当成所有事实失效，也不把值事实和内存内容事实混为一谈。
首版只使用已有分析能够证明的 Local／Const 等情况；未知条件保持原控制与效果约束。

### 放置约束

旧 `Refine(ControlOnly)` 的职责迁移到实际需要固定的操作：load、可能陷入的
指令，以及利用路径事实的计算。不能直接删去原控制约束，也不能通过递归
复制聚合每个叶子的 `Refine` 来传递它。物理访问降低时携带对应的控制与效果边。

## 凭据、作用域与维护

所有事实共用以下逻辑信息；存储可以是紧凑旁表和按需索引，不强制每项一个节点：

| 字段 | 含义 |
|---|---|
| predicate | 性质及其完整操作数，例如 `Variant(opt, Some)`、`UnsignedLess(i, len)` |
| witness | 构造器、分支出口、已声明的操作契约、`Assume` 或已验证推导 |
| scope | 可使用该事实的控制区域；Phi 操作数按对应前驱边查询 |
| value instance | 同一次动态定义；循环中静态 NodeId 相同不足以证明 |
| memory dependencies | 仅在涉及内存时记录相关状态、分配寿命或借用范围 |

`Proven` / `Assumed` 可作为来源分类保留，不再决定一个通用值转换节点的全部语义。
`Proven` 事实在其有效范围内不成立属于编译器错误；`Assume` 被违反属于源程序 UB。
**两类事实都受作用域约束。** `Proven` 不是任意上提许可；移出原作用域必须独立
证明目标处成立，或让移动后的操作不再依赖该事实且仍然安全。

CFG 重写、内联、特化、值替换及压实必须重映射凭据。保留的消费者要么获得新
凭据，要么失去该优化并恢复合法的保守形式；不能悬空引用已删分支。循环分析
不允许用待证明的自身或循环中的下一次定义形成自证。
证明边参与语义检查和分析失效，不作为机器数据边制造寄存器活跃区间。
影响优化决策的事实及其类型／调用摘要依赖必须可重建，并纳入相应内容身份或
缓存依赖；仅供诊断的源位置不进语义身份。事实旁表不是第二套可执行 IR。

## 运行需求与证明需求

| 消费方式 | 正常机器码需要的内容 |
|---|---|
| `VariantSwitch` / `VariantOf` | tag 或 niche 对应的位 |
| `VariantField` 的实际消费者 | 需要的字段及使物理访问合法的控制和内存条件 |
| 未内联调用、返回、真实存储 | ABI 或存储语义实际要求的表示 |
| 仅用于 `RequireDefined` / 证明记录 | 不增加运行时数据需求 |

需求分析至少区分执行消费者与证明消费者。后者可保持解释器所需引用，但不能
迫使布局阶段展开 payload、创建 ABI 槽或生成 load/store。

```text
v = Phi(MakeVariant(A, a), MakeVariant(B, b))
RequireDefined(v)
VariantSwitch(v)
```

分析可在各条前驱边分别查询 `a`、`b` 的 definedness，并对 switch 做按前驱拆分。
这不要求先生成新的运行时 A/B 判断。如果把要求实际搬到前驱，仍须证明不跨越
相关控制和执行边界；静态查询沿边进行不等于允许任意移动操作。
证明失败时保留紧凑要求，不退回“枚举所有变体并逐字段观察”的布局策略。

延迟物化不等于任意延迟读取：先前类型化读取形成的 owned 快照，不能被替换为
后续别名写入之后的字段 load。按需读取必须保持原读取时刻，或证明相关内存未变，
或保存快照。真实调用、volatile／atomic 访问和其他可观察效果不能因只剩证明
消费者而一并删除。

## 阶段、擦除与 ABI

1. R/S 保留语义要求及可解释的操作契约。源码意义的 `Return(value: T)` 和调用
   签名不因 `PassMode::Ignore` 而丢失；ZST、Never、MaybeUninit 各按自身语义处理。
2. `specialize` 的纯代入仍要求 R→S 相等；优化规则另行声明是相等还是 refinement。
3. S→L 有明确的要求擦除步骤：核对约束来源，导出后续优化仍需的作用域事实，
   将必要的控制／内存依赖落实到实际消费者，再擦除不产生运行时行为的要求。
   这一步按 refinement 验证，不要求目标在源 UB 输入上保留相同诊断点。
4. L 按执行需求选择表示和 ABI；可继续使用有范围的事实，但不为证明用途创建
   完整 enum 树。进入 Machine IR 时，凭据结束其编译期生命周期，实际控制与
   内存依赖必须已经落实。不能仅删除凭据就宣称操作可自由调度。

类型有效性不能偷偷查询未记录的泛型类型信息；涉及有效性规则的决策走
[孔位与答案依赖](generics-specialization.md#孔位)，与 `SizeAlign` 分开。
未知规则意味着不能利用该事实，不能猜测两个同大小类型具有相同有效性。

## 验证协议

| 源结果 | 目标结果 | 判断 |
|---|---|---|
| 有定义 | 引入 UB、错误结果或不允许的效果／终止行为 | 错编译 |
| 有定义 | 保持源允许的可观察行为 | 满足该输入上的 refinement 检查 |
| UB | 目标正常或 UB | 不能仅据此判错；先确认源 UB 判定有依据 |
| verifier 失败、Proven 事实失败、解释器不支持或执行超预算 | 任意 | 编译器错误或证据不足，不能冒充源 UB |

诊断保持验证与编译正确性验证分开。R/S 解释器或独立诊断记录可保留要求并报告
违反位置，诊断引用不进入发布代码的数据需求。CTFE 继续解释 Body。
迁移必须逐条标注采用 refinement 的规则及擦除边界；不得全局放宽所有差分断言，
也不得把 source UB 样例作为性能正确性的主要输入。有效输入上的输出、调用轨迹、
内存结果与终止行为保持强对拍。

## 迁移与验收

| 当前职责 | 目标职责 |
|---|---|
| `ObserveValue` 的 poison 消费 | `RequireDefined` 或操作自带契约；无新业务值 |
| 被笼统称为 Observe 的有效性要求 | producer 核对后明确为 `RequireValid<T>` 或对应操作契约 |
| `Refine(Variant, Proven)` | 变体凭据及消费者的控制依赖 |
| `Refine(Assumed)` | 独立 `Assume`／操作要求，加有范围的事实记录 |
| `Refine` 上的范围／非空 | 标量谓词事实 |
| `Refine(ControlOnly)` | 实际操作的放置依赖 |
| 整树布局观察 | 证明需求与执行需求分离，在声明的边界擦除要求 |

按契约登记、要求迁移、凭据迁移、布局与验证边界四步推进，不以本文替代实现
验收。无需同时重写整个解释器或引入完整权限系统。保留已冻结候选及其历史失败。

必须覆盖：活动／非活动 payload、嵌套 enum、部分初始化、MaybeUninit、padding、
零长数组、ZST／Never、循环下一轮 poison、分支不支配、失效内存凭据、别名写入后
快照、调用效果和 panic。负例还包括把 nonnull 当成可解引用、用父变体证明子变体。

结构门槛：给合法 enum 数据流增加冗余 definedness 要求，不增加发布机器码中的
分支、load/store 或值搬运；变体凭据不生成 payload 的逐叶 Refine 复制；证明用途
不迫使值物化。记录 S/L 节点、实际分支和搬运、代码体积、编译指令数及 runtime，
删除的要求数不能代替性能收益。PoC 冻结范围和性能门槛不变。
