# 不返回调用的控制流接缝

Fable G05 指出的限制来自内联器假设“每个被调函数至少有一个 Return”。
现在，直接以 `Unreachable` 终结或永远循环的函数，以及实参代入后只剩不返回路径的函数，
均可经过普通内联预算与合法性检查。

拼接先按原规则固定实参的定义性观察，克隆被调函数的效果与局部存储生命周期。
没有返回边时，不制造返回值、合流 Region 或假的效果 Phi。旧 Call 被移除后，
它的正常控制投影成为不可达；在检查下一个调用点前立即清理 CFG 和对应的值/效果 Phi 槽位。
被调函数内部的效果与循环保留，其他分支仍可到达的代码保留。

有 `no_inline` 或超过预算的调用使用已有函数属性证明。该证明必须与调用 ABI 一致。
`optimize_call_effects` 保留 Call，只给它一个终结出口并删除原正常延续，再做不可达清理。
已经直接终结的调用不重复改写；过期 ABI 的证明不被消费。

解释器差分覆盖先前效果、poison 实参、值与效果 Phi、没有返回结果的调用和无限循环。
真实 runner 位于 `crates/rustc_codegen_kfrc/tests/noreturn/run.sh`：与 LLVM 比较 4096 组满足
前提的输入，并在独立进程里比较不返回路径之前的效果和退出码。静态机器重定位另外确认
正常延续被删除，`unreachable_unchecked` 的调用边消失。

本轮不把所有通向 `Unreachable` 的分支当作可删除条件，也不实现完整 poison 精化规则。
不返回可以来自可观察的终结调用或无限循环；删除这些调用的效果需要额外证明。
