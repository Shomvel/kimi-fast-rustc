# 编译缓存：最小化

目标：缓存的**字节数**和**失效范围**都尽量小，且**不错误命中**。思路是只缓存重算昂贵、被多处复用的产物，键包含产物读过的全部输入、且只包含这些。

## 存什么

| 产物 | 存不存 | 键 | 理由 |
|---|---|---|---|
| AST、展开结果 | 不存 | — | 解析便宜；宏展开结果随依赖清单记录 |
| CheckedBody | 存 | 定义的语义哈希 + 依赖清单（下一节） | typeck/borrowck 昂贵；常量求值要用 |
| R 图（优化后）+ 孔位表 + mentioned | 存（即 metadata 里的函数体） | CheckedBody 哈希 + 被 R 级内联者的 R 图哈希 + R 级配置 | 每定义一份，下游共享 |
| S 图 | 只存**作为内联源**的 | 答案键 | 其余由 (R 图, 答案) 重算；内联源小，且下游每次内联都要用 |
| 调用摘要 | 存 | 答案键 | 几十字节，下游内联与 unwind 裁剪要用 |
| 机器码片段 | 存 | 答案键 + 读过的被调者摘要哈希 + 被内联者答案键 + L 级配置 | 最终产品，重算最贵 |
| 对象文件、链接产物 | 不单独存 | — | 由片段确定性拼接 |

嵌入实例（[generics-specialization.md](../ir/generics-specialization.md#嵌入实例)）不进缓存，它们只是调用者 S 图的一部分。

## 依赖清单：键要包含的读

每个产物在生成时记录它**实际读过**的东西，键由这份清单计算。walkthrough W03/W05/W08 找到的错误命中都是清单漏项：

| 读 | 谁会读 | 漏掉的后果 |
|---|---|---|
| 具体类型的布局（字段偏移、niche 编码、PassMode） | L 级，包括非泛型函数 | 上游给 struct 加字段，调用者命中旧偏移（W08 E7）；std 私有字段改变 niche（W03） |
| 被调者的调用摘要，即使没被内联 | S/L 级（`call` 还是 `invoke`、能否省拷贝、能否把 cap 留在寄存器） | 被调者变得会 unwind 或会捕获，调用者仍按旧摘要生成（W04、W05） |
| trait 选择读过的 impl 集合，含否定事实（“只有一个候选”“没有 impl”） | typeck、S 级 `Resolve` | 新增 impl 后命中旧选择（W08 E8） |
| 固有 impl 集合、不透明类型的隐藏类型 | typeck | 同上 |
| 真正求值过的 cfg 谓词 | 展开 | 只记读过的，避免改无关 cfg 时整体失效（W08 E9） |

配置不是一个笼统的“优化配置”，而是逐项列出、各自只进读它的产物：

| 配置项 | 进哪些键 |
|---|---|
| panic 策略 | S 图、摘要、机器码（发布的 R 图与它无关，见 [generics-specialization.md](../ir/generics-specialization.md#与-metadata-的关系)） |
| overflow-checks、debug-assertions | CheckedBody（它们改变 Body 的形状） |
| target、target features、CPU | 布局答案、L 级、机器码 |
| unwind 表、调试信息级别 | 对象拼接，不进机器码 |
| `--remap-path-prefix` | `Location` 表和调试信息，不进代码 |
| R/S/L 级各自的 pass 配置与燃料 | 对应级别的产物 |

## 源位置隔离

行号变化（文件前加一行）会改变所有 panic `Location` 和调试信息，但不应改变代码：

- 边界：`line!()`/`column!()`/`file!()` 展开出的值是**语义输入**，用到它们的定义随行号失效；行表按片段切分，行号相对定义的起始行；hygiene 信息不分离（rustc #47389：span 带 hygiene）。
- 代码通过符号引用 `Location` 条目（`loc.<定义>.<序号>`），条目内容（文件、行、列）在每个 crate 的 `Location` 表里，单独生成。
- `Location` 条目对 R/S/L 级**不透明**：优化器不能读它的内容（rustc O3 会把 `Location::caller().line()` 折成立即数 `27`，行号就进了代码，W08）。
- 调试行表同样是旁表，按片段单独生成。

结果：只移动行号的修改让机器码片段全部命中，只重写 `Location` 表和行表。rustc 增量构建在这个场景下 lib 重做 2 个 CGU、bin 重做 3 个，其中 4 个字节完全相同（W08 E2）。

## 和 rustc 增量的对比（W08 实测）

| 场景 | rustc 增量（`-Copt-level=3`） | kfrc 设计 |
|---|---|---|
| 注释 | 0 个 CGU 重做 | 全部命中 |
| 行号移动 | 5 个 CGU 重做，4 个字节相同 | 只重写 `Location` 表和行表 |
| 非泛型函数体 | bin 不重做：rustc 增量模式关闭了跨 crate 内联推断 | 同样不重做的前提是内联策略按构建模式区分（[optimization-pipeline.md](../ir/optimization-pipeline.md#内联策略)） |
| panic 策略 | 全部重做 | CheckedBody 与 R 图命中，从 S 级起重做 |

在非增量 release 构建下，rustc 修改注释也要重做 28.7% 的工作（SVH 覆盖整个 crate，本机 macOS 测量）。

## 分阶段

1. 先只缓存完整对象，键包含全部语义依赖。
2. 再逐层缓存已检查 Body、实例、优化图。

初期可以过度失效，但不能为命中率省略语义依赖。旧 Graph 缓存、新语义缓存、LLVM reference 产物分别使用独立的 namespace、schema 和输出目录；新链不读旧键。

## 跟踪不全的输入

环境变量、文件、外部工具等输入若无法完整跟踪，该任务不跨构建复用。build script 和过程宏的结果不默认视为纯函数。

每次命中都能说明匹配了哪些依赖版本，对象来源可追溯。缓存不确定时回退为重新编译，不能回退到另一个代码生成后端。

## 失效测试

逐项修改并确认预期的命中/失效：注释、函数体、公开签名、trait impl、泛型体、宏/hygiene、target feature、编译器升级、被调用者、布局、panic/overflow、pass 配置。

## 键里不得出现

调度参数（jobs、批次、CGU 划分）、本机绝对路径、未声明的环境变量、时间戳。反例：swift-driver 因 `-j` 不同就互不命中（#2249），sccache 因绝对路径不命中。

## 存储形式

- 内容寻址：同一内容（不同 crate、不同构建）只存一份。
- 紧凑编码：节点流 + 变长整数；跨产物引用用持久键（[ids.md](../ids.md)），不存会话 ID。
- 回收：每次构建写一份根清单，按最近 N 次构建的清单做标记回收。

## 指标

| 指标 | 对比对象 |
|---|---|
| 缓存总字节、每类产物字节 | rustc `target/` 中 incremental 目录和 rlib 大小 |
| 各编辑场景的命中率与重算量 | [W08](../../research/walkthroughs/w08-incremental-cache.md) 的场景 + [失效测试](#失效测试) |
| 错误命中 | 每个场景用“禁用缓存”构建对拍对象字节；故意漏记一次读取必须被测试发现 |
| 失效场景 | 首行插注释全部命中；`line!()` 使用处失效；上游新增私有项下游不失效（Swift #92617：加一个私有函数重编 1,110/1,114 个文件） |
| 每次命中的依赖解释 | 命中可追溯到清单条目 |
