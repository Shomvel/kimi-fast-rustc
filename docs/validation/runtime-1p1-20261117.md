# Runtime progress toward 1.1 × LLVM

The [latest validation](runtime-1p1-20261117-r3.md) records **1.12740784 × LLVM** after constant checked-multiplication and range-clamped comparison folding. The [constant-overflow checkpoint](runtime-1p1-20261117-r2.md) and this preceding `029378f` result preserve their measurement history.

This experiment starts at main `caeee81621248a379fe6efb5453bd93580ee5786`.
It keeps the original four libraries, all 13 workloads, iteration counts,
checksums, captured compilation commands and shared LLVM MIR0 sysroot.
The selected implementation changes general compiler policies and graph
transformations; it contains no function-name or workload-name dispatch.

The final-default instruction ratio is **1.13523155 × LLVM**, down from
main's **1.27091073 × LLVM**: a **10.6757%** reduction over all 13 workloads.
The 1.1 target remains unachieved; it requires another **3.1035%** reduction
in this same aggregate. [Structured acceptance data](runtime-1p1-20261117.json)
pins the source, native payloads, raw measurement archives and exact workload
counts.

## Implementation

The rustc shell uses ordinary call-site residual growth 160, costed inline
depth 1 and at most 65,536 added nodes per invocation. Hot growth stays at
256 with a shared extra-growth account of 512. Constant-argument scratch
preparation and the explicitly selected uniform residual policy remain at
32. The standalone SoN `InlineBudget` defaults do not change.

Three Layout transformations are enabled by default:

- Incoming predicate threading reuses existing scoped `PredicateFacts` on
  each incoming path. It examines at most 16 straight control steps and
  stops at joins. Existing loop rejection, growth limits and value/effect
  SSA repair apply; it does not bypass fixed operations.
- First-iteration peeling handles a small natural loop whose initially-zero
  scalar recurrence feeds checked multiplication. It keeps the residual
  loop, preserves guarded loads/calls/traps, and repairs values and effects
  at every exit. It peels at most one loop per function, with limits of
  64 controls, 128 cloned nodes and 256 added nodes; nested and irreducible
  loops are rejected.
- Scalar niche transport retains the scalar captured at the original typed
  read. It accepts only exact 1/2/4/8-byte niche enums with one fieldless
  direct-tag enum payload at offset zero, and fieldless remaining variants.
  The captured bytes can supply a guarded payload or a whole-value store
  without decoding and rebuilding the representation. Aliasing writes and
  calls cannot change that already captured SSA value. Other layouts retain
  the existing lowering.

The independent diagnostic ablations are `KFRC_LAYOUT_EDGE_THREAD=0`,
`KFRC_LOOP_PEEL=0` and `KFRC_SCALAR_NICHE_TRANSPORT=0`. Inline settings remain
explicitly configurable through `KFRC_INLINE_ORDINARY_GROWTH`,
`KFRC_INLINE_DEPTH` and `KFRC_INLINE_INVOCATION_NODES`.

## Measurement contract

The primary result is the geometric mean of user-mode dynamic instruction
ratios over the unchanged 13 workloads:

`exp(sum(log(candidate_instructions[w] / llvm_instructions[w])) / 13)`.

Each formal workload/crate count uses the median of three interleaved
measured repeats after one discarded warmup. Runtime uses frozen native
drivers with common LLVM callers. Compiles use the original four captured
commands. Every compile must reproduce its frozen object payload, every
runtime checksum must agree, and every perf event must have a positive
finite value and full coverage. Compile work is the sum of four per-crate
medians, not an end-to-end Cargo build. Text is the sum of the four library
object `.text` sizes. RSS is retained per crate rather than summed.

All arms run serially in one task-owned Linux x86-64 sandbox with 8 vCPU,
16 GiB RAM, Rust 1.94.1 and LLVM 21.1.8. Builds, profiles, transfers and
unpacking run outside measurement windows. Cycles and wall time are
separate observations; an instruction ratio is not a wall-time claim.

The profile collector decodes executed ELF addresses directly. This avoids
linear-disassembly errors at in-code jump tables. Audits require exact
function boundaries, complete address mapping and agreement between raw
self-cost sums and the trace total. Comparisons include inlined callees
within the same whole-driver boundary; function self costs cannot simply
be added across different inline decisions.

## Attribution screening

These results use one discarded warmup and one measured repeat. All eight
arms share the original inputs and counter contract. `EP` enables edge
threading and peeling; `Joint` adds scalar niche transport. Policy controls
use the unchanged main backend with explicit depth 1 and node cap 65,536.

|---|---:|---:|---:|

| Policy 160 | 0.91218033 | 1.175546 | 91,206 |
| EP 96 | 0.90953928 | 1.075598 | 80,610 |
| EP 160 | 0.89496739 | 1.199827 | 88,898 |

| Joint 160, selected | 0.89324289 | 1.197981 | 88,957 |
| LLVM MIR0 | 0.78683729 | 0.786531 | 45,987 |

The selected arm prioritizes the runtime objective. Joint 96 remains a
measured alternative with lower compile work and smaller text. Niche
transport alone improves Unicode reverse instructions by 2.626% at 96 and
2.477% at 160; the other twelve workloads are unchanged. Its all13 benefit
is 0.2045% / 0.1927%, with 20 / 59 additional text bytes. Combined benefits
are measured directly rather than compounded from independent screens.

Shared call-tree pricing was rejected after three-repeat comparison: the
existing policy was simpler and used fewer instructions, compiler work and
text. Existing Layout GVN also regressed the aggregate. Layout memory
forwarding alone increased all13 instructions by 0.0248%, used 0.75% more
compiler work and saved only 35 text bytes; its small extra benefit with
threading did not justify retaining it. These mechanisms are absent from
the delivered compiler.

One policy-160 screening attempt was invalidated because buffered transfer
traffic continued after the producer stopped. Its measurements are excluded.
The replacement reused the exact same frozen binaries after transfer and
hash verification completed. Successful native checks were retained.

## Correctness and acceptance

The combined experimental source passed 1,433 workspace tests, one ignored,
and 30 backend tests. Seven native arms passed all four original corpora and
all thirteen checksums; three disabled arms reproduced frozen main/96/160
object payloads exactly. This precedes, and does not replace, final-default
validation.

Differential fixtures cover exhaustive u8 loop inputs/limits, multiple exits,
reversed predecessor order, calls and failures, reconvergence, signed sparse
enum tags, wrapping niche codes, padding fallback and aliased source writes.
The scalar niche fixture includes 288 successful/failing S-versus-L cases.

The existing overlapping-lane fixture now checks the physical overlap
contract directly: one retained slot, all six stores, and 48 boundary-value
behavior cases. Its previous exact total-load count included tag reloads
that these optimizations can legally remove. Legacy inline publication
fixtures bind their original depth/node limits explicitly in both preparation
and emission; their completion, ownership and defined/poison assertions
remain. The semantic-IR report counts both structured CGSCC inlines and
anchored emission records, since an emission-only count misses calls already
removed during preparation. Native behavior, provenance, permissions and
expected whole-crate rejections retain their original checks.

The actual-default release source passes the original native gate: switches,
byte ladders, inline temperature (including both cold abort paths), lane
promotion, static and narrow loads, noreturn, program data, storage
representation, scalar/entry/Cargo, generated scalars, semantic IR, semver,
its dynamic probe, scalar ABI and the archived narrow-return fixture. All13
native outputs pass. The four captured libraries produce identical objects
at one and four codegen threads, and match the previously frozen Joint 160
payloads. Disabling all three transforms reproduces Policy 160; disabling
niche transport reproduces EP 160.

Workspace results are reused from the identical production source in v1;
backend results are from v2 after the explicit fixture-budget repair. V3
changes only Rust formatting and documentation. The crate patch bytes are
audited equal to the source used by the final release build. Corrected
Rust-2024 formatting checks pass for every changed Rust file; unrelated
accepted-main formatting debt is retained rather than reformatted.

## Remaining substantial work

Four final-default Callgrind traces use the original iteration counts:
400,000 semver parses, 400,000 requirements, 500,000 duration parses and
400 reverse-grapheme runs. Exact executed-address decoding, raw self sums,
driver category sums, function boundaries and checksum/hash pins pass.
Frozen main/96/160/LLVM traces are reused; no workload was rerun to repair
offline reporting. These traces locate costs; the separate three-repeat
formal counters above remain the aggregate acceptance result.

| Final workload | Instructions/LLVM | Largest retained self cost, million instructions | Whole-driver excess branches | Excess comparisons | Excess loads |
|---|---:|---|---:|---:|---:|
| semver req | 1.515717 | comparator 89.47 | 26.33 M | 25.20 M | 25.53 M |
| semver parse | 1.253929 | numeric_identifier 81.07 | 9.07 M | 11.13 M | 4.00 M |
| duration parse | 1.403732 | Parser::parse 241.95 | 35.70 M | 41.50 M | 41.95 M |
| Unicode reverse | 1.288370 | prev_boundary 390.73 | 44.45 M | 30.27 M | 34.24 M |

Category excess means final minus LLVM within the same whole linked-driver
ELF boundary. Shared-object work remains in total instructions but outside
these categories; stack operations and arithmetic with memory operands have
their own categories. Inclusive call-edge costs overlap and are not added.
Individual function self costs also depend on inlining. In semver parse,
register moves add another 13.80 million instructions over LLVM. Duration
parse and Unicode reverse have fewer call instructions than LLVM while
retaining much more load and control work.

Two additional diagnostic compiles retain complete S-input, S-final and
L-final graphs. Both captured-library object payloads exactly match the
frozen final defaults. Layout threading affects 26 regions in prev_boundary,
29 in Parser::parse and 21 in parse_unit, cloning 41/23/45 values; these three
functions have no peeled loops. In the final S graph, prev_boundary retains
`p0:Unique(88)`, an effect Phi `n60` at loop region `n7`, and a field-0
`LoadValue n61` after that Phi. Its mutable state remains addressable.
Parser::parse retains a local Parser whose address is passed to parse_unit
with `Unique(32)` permission, plus typed iterator loads and stores after
inlining. These graph facts identify where to investigate the load/control
gap; they do not establish that every dynamically executed load is removable.

The next substantial hypothesis is a scalar snapshot Phi across loop
backedges for borrowed mutable fields. Existing
`transforms/memory/forward.rs` crosses effect Phis only when all incoming
paths reach the same memory version; it does not construct a value Phi from
different reaching stored values. A bounded S-level extension could create
a value Phi when every incoming edge supplies a valid previously observed
or stored snapshot of the same typed place, then replace repeated reads.
Keep physical writes and initial reads at their original points. Explicit
Unique-reference, alias, call and lifetime proofs are required: calls
receiving the root or a derived pointer, unknown writes, opaque/reborrow and
lifetime boundaries invalidate the snapshot. Guarded enum payloads and
uninitialized lanes must remain guarded. Existing contracts can justify
preservation across unrelated calls only when they prove it.

Existing S promotion handles unescaped local slots; L lane promotion and
Cranelift already promote much private physical storage. The proposed
extension addresses typed state that survives their existing escape and
merge restrictions. It is not implemented or included in this result.
Reaching 1.1 requires another 3.1035% reduction over all thirteen workloads;
if only these four workloads improve, they need roughly 9.74% geometric-mean
reduction each. That is an experimental success threshold, not a predicted
benefit.

The legacy trace parser can retain an object label across function records
and overwrite per-address exports for aliased symbols. Raw traces and JSON
remain immutable. Derived call tables repair object labels only for a unique
exact-function owner; ambiguous labels are retained. Derived instruction
tables accumulate raw per-function dynamic counts at each exact ELF address.
For semver req, the 77 aliased addresses now sum exactly to the whole-driver
352,738,298 instructions. Function self costs and the independent formal
counter result do not depend on these offline table repairs.

Raw commands, inputs, binary hashes, counters and traces are retained outside
Git. This repository publishes their identities and summarized results,
without claiming a public download location.

## Reproduce correctness checks

Use Linux x86-64 and the pinned Rust 1.94.1 toolchain with `rustc-dev`.
From the repository root, with fresh output directories:

```sh
RUST_TEST_THREADS=1 cargo test --workspace
RUSTC_BOOTSTRAP=1 cargo test --manifest-path crates/rustc_codegen_kfrc/Cargo.toml --lib
RUSTC_BOOTSTRAP=1 cargo build --release --manifest-path crates/rustc_codegen_kfrc/Cargo.toml
export KFRC_VERIFY=full KFRC_CRANELIFT_VERIFY=1
backend="$PWD/crates/rustc_codegen_kfrc/target/release/librustc_codegen_kfrc.so"
bash crates/rustc_codegen_kfrc/tests/semantic-ir/run.sh "$backend" /tmp/kfrc-runtime-semantic
bash crates/rustc_codegen_kfrc/tests/scalar-abi/run.sh "$backend" /tmp/kfrc-runtime-abi
bash crates/rustc_codegen_kfrc/tests/p0-scalar/generated/run.sh "$backend" /tmp/kfrc-runtime-generated 1 30 40
```

These entry points reproduce workspace/backend and selected native regression
checks, not the whole archived gate or formal benchmark. Reproducing formal
numbers additionally requires the pinned captured commands, suite, shared
MIR0 sysroot and driver identities recorded in the structured receipt.
