# Range-clamped integer comparison

Latest accepted checkpoint: [monotone RPO dominance queries](runtime-1p1-20261117-r4.md).

The actual default uses **1.12740784 × LLVM MIR0** dynamic instructions over the unchanged thirteen workloads. Relative to accepted `6c8fafb`, Unicode reverse instructions fall **4.2696%**, the all-thirteen geometric mean falls **0.3351%**, and the other twelve instruction counts remain within counter variation. Four captured compiles use **0.1493%** more instructions; object text falls **200 B**. This is an accepted runtime/compile tradeoff. The objective remains incomplete: 7/13 runtime instruction ratios, 1/4 compile instruction ratios and 0/4 crate text ratios meet 1.1.

Layout can encode an unsigned integer selection as `select(x <= K, zext(x), C)` using masks. When `C > K`, comparing this selection with `E <= K` reduces to comparing the original `x` with `E`; comparison with `C` reduces to `x > K`. The bounded matcher handles equality and inequality, optional same-width signedness casts, and only ordinary unsigned source integers up to 64 bits. It retains the original source operand and its poison behavior. Other consumers retain the original selection. Unsupported patterns return without allocating nodes; a successful rewrite adds at most two nodes. `KFRC_CLAMP_COMPARE=0` independently restores the preceding path.
