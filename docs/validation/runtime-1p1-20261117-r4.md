# Monotone RPO dominance queries

The actual default reduces the four captured compiles' instruction sum **1.51194%** relative to accepted `bc62fa9`, from **10,842,263,212** to **10,678,334,294**. Every crate improves in all three paired repeats. Compile instructions remain **1.501094 × LLVM MIR0**. All library object payloads, text sizes and runtime driver bytes equal the preceding default. The unchanged thirteen runtime instruction ratios have geometric mean **1.127407 × LLVM**; this is a compile optimization. The all-metrics 1.1 objective remains incomplete.

Dominator positions use reachable reverse postorder. Every proper dominator precedes its child, so a query for `a` can stop when the parent walk reaches a position no greater than `a`. The query now follows `idom[b]` only while `b > a`, then returns `a == b`. Construction, storage, CFG snapshots and other algorithms retain their existing paths. `KFRC_DOMINANCE_RPO=0` restores the complete parent walk for ablation.
